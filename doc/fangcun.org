#+title: 方寸（fangcun）

Each 一隅（yiyu） is an independent Org note root.  Fangcun indexes ID-based
nodes from multiple yiyu roots in a local SQLite database.  Configure each
yiyu with an identifier, display name, and root directory:

#+begin_src emacs-lisp
(setq fangcun-yiyus
      '((personal :name "Personal" :root "~/notes/personal")
        (work :name "Work" :root "~/notes/work")))
#+end_src

=M-x fangcun-yiyu-add= selects an existing local directory, records its ID and
display name in the Custom file, and immediately synchronizes the index.
=M-x fangcun-yiyu-remove= removes a selected yiyu from the saved configuration
and index after confirmation.  It never deletes the root directory or its
notes.  Yiyu IDs must be unique, and yiyu roots cannot overlap.

=M-x fangcun-file-node-create= opens a new unsaved Org file with a file-level
ID.  It uses the current file's yiyu and directory when possible, otherwise it
selects a configured yiyu.  The file prompt can navigate to an existing
subdirectory or name a new one below that yiyu.  An optional title is used
verbatim as the suggested file name, which is always shown for confirmation.

=M-x fangcun-heading-node-create= gives the current heading its own local ID.
It returns an existing heading ID without replacing it.  Save the file to make
a newly created heading node available through the Fangcun index.

Every new relative path component is checked for characters and reserved names
that cannot be shared across the supported platforms.  Invalid input remains in
the prompt for editing; Fangcun does not rewrite it.  The path must stay inside
the selected yiyu, and its name must end with =.org= and must not already exist.
Fangcun creates missing parent directories after the path is accepted.

=M-x fangcun-db-sync= synchronizes the database with the =.org= files below the
configured yiyu roots.  It indexes added or changed files and removes files
that no longer exist.  The first synchronization and a change to the yiyu
configuration rebuild the database.  =M-x fangcun-db-rebuild= always indexes
every file again.

The first Fangcun command in an Emacs session performs an incremental sync
before reading the database.  This reconciles changes made while Emacs was not
running without doing any Fangcun work in sessions that never use it.

Fangcun uses a Rust helper to enumerate files and recursively monitor their
directories.  File events are combined and processed when Emacs is idle.  The
helper reports its source build ID when it starts.  If it is missing or does
not match the tracked build ID, Fangcun continues the current sync with Emacs
file operations and asks Cargo to build the helper asynchronously.  The build
output is available in =*Fangcun Helper Build*=.  A missing Cargo or a failed
helper disables live external-change monitoring, but saving, reverting, manual
synchronization, and complete rebuilding continue to work.

=M-x fangcun-native-build= rebuilds the helper after changing its Rust sources.
Cargo refreshes the tracked source build ID during every build.
The command-line and JSON interface is documented in the
[[file:../native/fangcun-watch/README.org][native helper protocol]].

A file-level =ID= creates a file node.  A heading =ID= creates a heading node.
File nodes use =#+title= when present and otherwise use their relative file
name without the extension.  A heading without text uses its ID as its display
title.  The =ALIASES= property assigns alternative names to either kind of
node.  Separate aliases with spaces and quote an alias that contains spaces:

#+begin_src org
:PROPERTIES:
:ID:       42
:ALIASES:  AI "Artificial Intelligence" 人工智能
:END:
#+end_src

The synchronization also indexes =id:= links owned by the nearest enclosing
node.

After the database is initialized, =M-x fangcun-db-update-file= replaces the
indexed nodes and links for the current saved Org file without processing the
other yiyu files.  Saving a configured yiyu file performs the same update
silently.  Reverting a visited yiyu file also updates it from disk.  Renaming or
deleting a file through Emacs updates the database immediately.  These exact
updates remain active while native monitoring is running; duplicate native
events are discarded by comparing the indexed file state.  Set
=fangcun-db-update-on-save= to =nil= to disable updates after saving.

=M-x fangcun-node-find= completes over the titles and aliases of indexed nodes.
Each candidate shows its owning yiyu and relative file.  Selecting one opens
its file and moves to the matching Org ID.

=M-x fangcun-node-insert= uses the same completion to insert an =id:= link at
point.  The selected title or alias becomes the link description.

=M-x fangcun-node-set-tags= edits the local tags of the node at point.  File
nodes use =#+filetags=; heading nodes use heading tags.  Fangcun indexes each
node's effective Org tags, including tags inherited according to Org's current
settings.  Completion candidates display these as =#tag= tokens, so node find
and insert can search by one or more tags.  Fangcun rejects names outside
Org's tag syntax instead of rewriting them.

Org controls which tags heading nodes inherit.  For example, the following
keeps type tags on a file node while allowing its other file tags to propagate
to heading nodes:

#+begin_src emacs-lisp
(setq org-use-tag-inheritance t
      org-tags-exclude-from-inheritance
      '("project" "person" "reference"))
#+end_src

ID links may include an Org search suffix, such as
=id:NODE-ID::*Heading= or =id:NODE-ID::target=.  The suffix selects a location
inside the target node, while Fangcun attributes the backlink to the node ID.

Following an ordinary Org =id:= link resolves indexed Fangcun nodes through
the Fangcun database.  IDs not stored by Fangcun continue through Org's normal
lookup.

=M-x fangcun-backlink-find= completes over nodes linking to the node at point.
Each source node appears once.  Selecting one opens its first indexed link to
the current node.

=M-x fangcun-backlinks= opens a read-only buffer containing every indexed link
to the node at point.  Occurrences are grouped by their source node and show the
source line as a preview.  =RET= visits the link, =gr= refreshes the buffer, and
=q= closes its window.

The note map provides the frequent Fangcun commands under the global leader:

- =SPC n c= creates a node from the current heading.
- =SPC n f= finds a node.
- =SPC n i= inserts a node link.
- =SPC n n= creates a file node.
- =SPC n t= sets the current node's local tags.
- =SPC n b f= finds a backlink to the current node.
- =SPC n b v= displays backlinks to the current node.

The database defaults to =var/fangcun/fangcun.sqlite= below
=user-emacs-directory=.

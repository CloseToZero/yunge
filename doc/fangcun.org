#+title: 方寸（Fangcun）

Fangcun indexes Org notes by ID across one or more 一隅（yiyu） roots. Each yiyu is
an independent directory with an ID and a display name. Notes remain ordinary
Org files; the index supports finding nodes, links, tags, and backlinks.

* Configure note roots

Create the directories first, then configure non-overlapping roots with unique
yiyu IDs:

#+begin_src emacs-lisp
(setq fangcun-yiyus
      '((personal :name "Personal" :root "~/notes/personal")
        (work :name "Work" :root "~/notes/work")))
#+end_src

=M-x fangcun-yiyu-add= selects an existing local directory and saves it to the
Custom file. =M-x fangcun-yiyu-remove= removes a root from the configuration and
index after confirmation; it does not delete notes. Both commands synchronize
the index after the change.

After editing =fangcun-yiyus= yourself, evaluate the setting and run
=M-x fangcun-db-sync= to apply it immediately. The next node search also
picks up changed settings. If synchronization fails, correct the
reported problem and synchronize again; monitoring the previous roots stops
when the configuration changes are applied.

* Create and save nodes

=M-x fangcun-file-node-create= prepares a new Org file with a file-level =ID=.
The prompt starts in the current yiyu and directory when possible, and accepts
a new subdirectory below the chosen root. Confirm the suggested path, then
*save the buffer*: the new file is indexed after it exists on disk. Paths must
stay inside their yiyu, end in =.org=, and use portable names; existing files
are not overwritten.

=M-x fangcun-heading-node-create= adds an =ID= to the current heading, or keeps
its existing one. Save the file to make a new heading node searchable. File
nodes use =#+title= when present and otherwise use their yiyu-relative path
without =.org=; headings use their text, or their ID if the text is empty. Add
alternate names to a node's property drawer with =ALIASES=:

#+begin_src org
:PROPERTIES:
:ALIASES:  AI "Artificial Intelligence" 人工智能
:END:
#+end_src

Fangcun indexes =id:= links under their nearest file or heading node. Ordinary
Org links remain valid; an ID not indexed by Fangcun continues through Org's
normal lookup.

* Find, link, and tag

=M-x fangcun-node-find= searches indexed titles, aliases, and tags, then opens
the chosen node. Candidates identify the yiyu and relative file; headings also
show their outline path. =M-x fangcun-node-insert= inserts an =id:= link using
the same completion. A selected region becomes the link description; on an
existing =id:= link, the command changes its target and keeps its description.
Otherwise it uses the selected title or alias.

=M-x org-insert-link= still supports every standard Org link type. Its =id:=
completion offers Fangcun nodes as well as Org's native heading completion.

=M-x fangcun-node-set-tags= edits local tags on the node at point: =#+filetags=
for a file node, heading tags for a heading node. Fangcun indexes effective
tags, including inheritance allowed by your Org settings. Search candidates
show them as =#tag= tokens. For example, exclude type tags from inheritance:

#+begin_src emacs-lisp
(setq org-use-tag-inheritance t
      org-tags-exclude-from-inheritance
      '("project" "person" "reference"))
#+end_src

* Follow links and check the graph

=M-x fangcun-backlink-find= lets you choose a node linking to the node at point,
then opens its first matching link. =M-x fangcun-backlinks= shows every indexed
occurrence, grouped by source node. An =id:= link may include an Org search
suffix such as =id:NODE-ID::target=; the backlink still belongs to =NODE-ID=.

=M-x fangcun-check= scans saved files in every configured yiyu for duplicate
IDs, ID links without an owning node, and unresolved targets. It does not edit
notes or the database and can run even when synchronization fails.

In both results buffers, =RET= visits the item at point. Yunge's Evil Normal
state also provides =gr= to refresh the results and =q= to close the window.

In Yunge's leader map, the common commands are:

| Key         | Action                |
|-------------+-----------------------|
| =SPC n c=   | Create heading node   |
| =SPC n n=   | Create file node      |
| =SPC n f=   | Find node             |
| =SPC n i=   | Insert node link      |
| =SPC n t=   | Set local tags        |
| =SPC n b f= | Find backlink         |
| =SPC n b v= | Show backlinks        |
| =SPC n C=   | Check note graph      |

* Keep the index current

The first use of the index in an Emacs session synchronizes saved files before
reading it. Saving or reverting a configured Org file updates that file's
index entry; renaming or deleting it through Emacs updates the index too.
=M-x fangcun-db-update-file= updates the current saved file explicitly.
Set =fangcun-db-update-on-save= to =nil= to disable updates after saving.

The index and backlink previews describe saved text. Save your edits before
looking for a new node or link. If another application changes a note while
its buffer is open, synchronization reads the file on disk and leaves your
buffer untouched. Revert the buffer when you want to load those changes;
save or otherwise keep any unsaved work before reverting.

** Watch external edits

An optional Rust helper scans roots and watches changes made outside Emacs.
Fangcun processes its events after an idle delay, so an external save may take
a moment to appear in searches. If the helper cannot run, use
=M-x fangcun-db-sync= after external changes; Emacs can scan the files itself.

The helper builds through Cargo when needed. Build output appears in
=*Fangcun Helper Build*=. After changing its Rust sources, use
=M-x fangcun-native-build= to rebuild it. See the
[[file:../native/fangcun-watch/README.org][native helper guide]] for its command-line protocol.

To turn off the helper in a running Emacs, evaluate:

#+begin_src emacs-lisp
(setopt fangcun-native-helper-enabled nil)
#+end_src

This stops monitoring, cancels any helper build, and discards queued events.
Saving notes in Emacs and running synchronization commands still update the
index. Set the option to =t= to enable the helper again; monitoring starts if
Fangcun is already in use, or on its next use otherwise. You can also change
the option through =M-x customize-variable=.

You may explicitly run =fangcun-native-build= while the helper is disabled to
prepare the executable. A successful build leaves monitoring disabled.

** Recover missed changes

Run =M-x fangcun-db-sync= to add, update, and remove index entries to match
saved Org files. This is also useful after a bulk edit or when searches show
old results.

When moving a node between files, keep its =ID= and save both files, then run
=M-x fangcun-db-sync=. If synchronization reports a duplicate ID, use
=M-x fangcun-check= to find it, correct and save the notes, and synchronize
again. A failed synchronization or file-event batch keeps the previous index;
queries may still show the old locations until synchronization succeeds.

If a note root becomes unavailable, for example after disconnecting a drive,
full synchronization and native file-event updates stop and report the missing
directory. The previous index stays available. Restore the directory at its
configured path, then run =M-x fangcun-db-sync= to catch up with saved changes.

If the index appears damaged or still disagrees with saved notes after a sync,
run =M-x fangcun-db-rebuild= to parse every file again. Synchronization and
rebuilding change only the index; they never rewrite notes.

* Store the index elsewhere

The database and helper build files live under =fangcun-state-directory=, which
defaults to =var/fangcun/= below =user-emacs-directory=. Set this before loading
Fangcun to choose another location. An explicit =fangcun-database-file= chooses
the database path independently.

For the parsing and indexing contracts, see [[file:fangcun-development.org][Fangcun development]].

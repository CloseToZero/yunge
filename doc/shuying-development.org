* Request a render

Shuying returns a cached artifact or asks a backend to produce one. The
caller decides where to display the result and whether it is still relevant
when it arrives. For Org editing and toolchain setup, see the
[[file:shuying.org][preview guide]].

Load =shuying-latex= to register the LaTeX backend. This example renders one
formula with XeLaTeX and reports the resulting SVG path:

#+begin_src emacs-lisp
(require 'shuying-latex)

(shuying-render
 (make-shuying-render-spec
  :source "\\(x^2+y^2=z^2\\)"
  :preamble "\\documentclass{article}\n\\usepackage{xcolor}"
  :engine '("xelatex" "-no-pdf")
  :backend 'shuying-latex
  :backend-options '(:converter ("dvisvgm"))
  :output-format "svg"
  :foreground "Black"
  :background "Transparent"
  :scale 1.0
  :cache-version shuying-cache-format-version)
 (lambda (artifact error-data)
   (if error-data
       (message "Preview failed: %s" (error-message-string error-data))
     (message "Preview: %s" (shuying-artifact-path artifact)))))
#+end_src

The specification identifies the cached result. Include every rendering
input in its fields: source, preamble, engine, backend and backend options,
output format, colors, scale, page width, equation number, and cache version.
Keep the specification unchanged until completion.

=shuying-render-batch= takes a list of =(SPECIFICATION . CALLBACK)= pairs.
Identical pending specifications share one job. Different specifications
may share a backend call when the backend can render them together.

The callback receives =(ARTIFACT ERROR-DATA)=. Success supplies an artifact
and nil error; failure supplies nil artifact and an Emacs condition such as
='(error "Rendering failed")=. Read the completed file with
=shuying-artifact-path= and its display properties with
=shuying-artifact-metadata=.

* Handle completion

Request validation, batch grouping, and temporary-file preparation happen
before Shuying accepts a submission. If preparation fails, the render call
signals an error without invoking any of that submission's callbacks or
changing existing jobs. Correct the cause and submit again. Once accepted,
rendering and cache-publication failures are delivered through callbacks.

A callback can run before the render call returns, including on a cache hit.
Initialize the display target before submitting its request. A callback may
submit another request; if it signals an error, Shuying reports a warning
and continues notifying other callers.

Rendering can also finish after the caller has edited the source, removed
the preview, or killed the buffer. Before displaying an artifact, check that
the target is alive and that the result belongs to its current request.
The Org integration associates each request with an overlay generation and
discards results from older generations. A discarded display result can
still serve other callers through the cache.

* Read formulas from Org

=shuying-org-source= reads formulas without loading the renderer or enabling
previews. It owns the buffer's formula catalog and equation numbering.
=shuying-org= uses those results to track editing, request renders, and display
previews; overlays and viewport timers belong to that display layer.

=shuying-org-source-at-position= reads the formula containing a position in
the accessible buffer. Its optional =include-end= argument also accepts the
formula's end position, which is useful when point has just left its source.
This local query does not compute equation numbers. It lets editing commands
track point without parsing the entire document on each movement.

For rendering, call =shuying-org-source-formulas= to obtain formulas in document
order with their numbering context. It reads the whole buffer, including text
outside narrowing. =shuying-org-source-in-ranges= selects formulas overlapping
any supplied =(BEGINNING . END)= range and retains that document-wide numbering.
Both operations preserve point and narrowing.

Each =shuying-org-formula= describes its =source=, buffer bounds, whether it is
block math, whether it occupies its lines alone, and its initial equation number
when applicable. =shuying-org-formula-bounds= returns the bounds as a pair;
the end is exclusive and leaves an environment's final newline outside the
preview. Treat these records as read-only snapshots of the text that was read.
An edit can invalidate their positions as well as their source and numbering.

After text changes, the next catalog query refreshes the stored formulas.
=shuying-org-source-current-p= reports whether the catalog describes the current
text; =shuying-org-source-reset= discards it explicitly, as after a buffer revert.
The display layer rechecks visible previews when a changed formula could affect
later numbering. Unchanged rendering inputs reuse their existing artifacts.

* Implement a backend

Call =(shuying-register-backend name function batch-key-function)=. The
optional batch-key function receives a specification and returns a key.
Specifications with equal keys for the same backend can share a call.
Without a key function, all requests for that backend are considered
compatible. For example, the LaTeX backend groups formulas that share a
preamble, engine, and rendering settings into one document.

The renderer receives a list of =shuying-backend-request= objects and a
completion function. Read each request's =specification=, write its result
to =output-file=, and set =metadata= if the front end needs display properties.
Call =(funcall complete request nil)= on success or
=(funcall complete request error-data)= on failure, exactly once per request.
Do not modify the output file or metadata after completion.

Completion may happen after the renderer returns. If the renderer signals
an error, Shuying fails its unfinished requests and keeps already completed
results. A batch holds its scheduler slot until every request finishes;
=shuying-max-concurrent-batches= limits concurrent backend batches.

The backend owns its processes and working files. Shuying owns publication
of the completed output and metadata into the cache. Front ends own display
state; the scheduler does not depend on Org buffers or overlays.

* Prepare LaTeX preambles

=shuying-latex-preamble= owns preparation shared by render batches: MiKTeX
package checks and precompiled formats. =shuying-latex= owns each batch's
document, compiler, converter, and working directory. A batch waiting for
preparation does not own the shared preparation process or its files.

=shuying-latex-preamble-prepare= takes a render specification, a resolved
engine command, and a callback receiving =(FORMAT-KEY FORMAT-FILE ERROR-DATA)=.
The callback can run immediately or after a process exits. A preparation
error prevents rendering. A nil format file with no error means the batch
should compile its full preamble. Keep the format key opaque; it identifies
the reusable format when reporting a failed format later.

MiKTeX package checks run one at a time so concurrent batches do not start
competing package installers. Requests with the same preamble and engine
share a check. A failed process is retried once, since MiKTeX may have installed
the missing package before exiting unsuccessfully. Successful checks are
remembered for the session; a failed check can be requested again. Ordinary
compilation and format building disable the MiKTeX installer.

Precompilation is optional and currently applies to the =latex= engine.
Compatible requests share one format build. A failed precompile process falls
back to the full preamble and suppresses further builds of that format for the
session. Failure to prepare its input files instead reports an error.
A waiting callback's error is reported without preventing other waiters from
receiving their results. Preparation releases its shared state and cleans up
its work before notifying callers; cleanup failures produce warnings.

When compilation with a cached format fails, the render batch retries once
with the full preamble. Only a successful retry establishes that the format
is unusable. The batch then calls =shuying-latex-preamble-invalidate-format=
with the key and file it received during preparation. Failure to delete that
file must not interrupt conversion of the successfully compiled document.

=shuying-latex-preamble-insert= writes the complete preview preamble into the
current buffer. Both full-document rendering and preparation use it so their
package and driver settings agree. Successful jobs remove their temporary
work and logs. Logs from failed processes remain available for inspection.

#+title: 数影（Shuying）

Shuying is an independent Emacs library for responsive, accurate LaTeX
previews.  Org is its first front end, but rendering, scheduling, and caching
belong to Shuying rather than to Org-specific configuration.  The design is
free to evolve with actual use instead of preserving unused compatibility.

* Interaction

The Org integration has one small interaction boundary:

- Point outside a LaTeX fragment shows its image.
- Entering a fragment reveals its source.
- Fragment display state belongs to the buffer rather than to a window.  When
  several windows show the same buffer, entering or leaving a fragment in the
  selected window changes that fragment in all of them; inactive windows do
  not retain independent editing states.
- Editing marks the fragment dirty without starting work for every keystroke.
- Leaving a dirty fragment requests a new preview.
- A late result from an older request cannot replace a newer result.
- When an Org buffer is first displayed, scrolled, or resized, newly visible
  fragments are requested without compiling every off-screen fragment.  All
  windows showing the buffer contribute their visible ranges.
- Rapid viewport changes replace the pending viewport update, so rendering
  starts from the final visible range after scrolling settles.
- Displaying rendered images rechecks the viewport until formulas exposed by
  the changed layout are also populated.
- Saving an Org buffer or changing the active theme rechecks visible previews.
  Only formulas whose rendering inputs changed request new artifacts.
- Inline previews use the height and depth reported by =dvisvgm= to follow the
  surrounding text baseline.  Their display height is expressed in =em=, so
  buffer-local font scaling resizes cached SVGs without rerunning LaTeX.
- SVG artifacts are tightly cropped.  The Org front end, rather than TeX's
  page box, centers block math in the window text area.  Customize
  =shuying-org-block-math-alignment= to retain the source column instead.
- Block math is centered only when its opening and closing physical lines
  contain no other text.  Non-standalone block math remains previewed at its
  source column because an overlay cannot reproduce TeX's line break faithfully.
- Whitespace-only formulas are left as source and are not rendered.  Artifacts
  with no visible geometry also remain source-visible without reporting an
  error or being rendered again.

The Org adapter keeps a buffer-local catalog of fragment bounds and source
text.  It builds the catalog with Org's parser, reuses it while the text is
unchanged, and rebuilds it the next time fragments are enumerated after an
edit.  Visible ranges are matched against the position-ordered catalog
without reparsing the buffer.

Only automatic viewport discovery is delayed.  Manual previews and previews
requested after leaving an edited fragment enter the renderer immediately.

Numbered LaTeX environments follow their order in the Org buffer.  Each row
of a multi-equation environment advances the counter unless it uses
=\nonumber=, =\notag=, or =\tag=; row breaks inside nested environments do
not affect the outer sequence.

Manual commands preview or clear a fragment, region, section, or buffer.
Continuous rendering while typing is separate from this basic interaction and
only belongs here if it proves useful in practice.

* Library boundary

The source layout is:

- =shuying.el= owns render specifications, jobs, backends, and the cache.
- =shuying-latex.el= runs batched LaTeX and dvisvgm processes.
- =shuying-org.el= finds Org fragments and manages their display lifecycle.
- =yunge-org.el= enables Shuying and assigns user-facing key bindings.

The core must not depend on Org syntax or overlays.  An adapter supplies source
text and context, then consumes completed render artifacts.

* Render specifications

A render specification contains every input that can change an artifact:

- source text;
- preamble and TeX engine;
- backend, backend options, and output format;
- foreground and background colors;
- scale, page width, and equation-numbering context; and
- a Shuying cache-format version.

The hash of the complete render specification is the cache key.  A cache hit
therefore means that all rendering inputs match, not merely that the source
text matches.  Each cached image has a small sidecar containing backend
metadata such as width, height, and depth.  The renderer owns that metadata;
front ends decide how to apply it to their display system.

=M-x shuying-clear-cache= removes completed artifacts and their metadata.
It preserves precompiled formats, render work, and diagnostic logs, and
refuses to run while rendering is in progress.

An Org fragment also has independent display and work state:

- display: source or image;
- content: clean or dirty; and
- work: idle or rendering, with a monotonically increasing generation.

The generation is checked when asynchronous work completes.  This makes stale
result rejection part of the model instead of an overlay-specific workaround.
Each displayed overlay also remembers its render specification hash.  A later
viewport pass can therefore distinguish an existing preview from one rendered
with an obsolete preamble, color, scale, or backend configuration.

* Foundations

Shuying owns fragment discovery, display state, render specifications, cache
keys, artifact locations, and the backend protocol from the beginning.  These
concepts form the stable boundary between front ends and renderers.

A backend accepts a compatible group of render requests and a completion
function.  It completes each request independently, either immediately or
asynchronously.  This keeps process management out of the Org adapter.

* Scheduler and LaTeX renderer

The scheduler accepts requests from every Shuying front end.  Identical render
specifications share one pending job.  Compatible batches enter a FIFO queue,
and at most =shuying-max-concurrent-batches= are owned by backends at once.  A
batch keeps its scheduler slot until every request in it has completed.

The direct =latex= and =dvisvgm= backend uses this pipeline:

1. Return cache hits immediately.
2. Collect misses with compatible preambles and rendering options.
3. Reuse or asynchronously build one precompiled format for the preamble.
4. Compile each compatible batch in one temporary TeX document.
5. Convert every page to a tightly bounded SVG and collect its =dvisvgm=
   geometry.
6. Map each SVG and its metadata back to the originating request.
7. Publish each artifact and metadata sidecar atomically.
8. Check the request generation before changing a buffer display.

LaTeX and dvisvgm run as a nonblocking process chain.  A batch uses an isolated
working directory below =var/shuying/work/=.  Successful work is removed after
its artifacts are published; failed work preserves a process log buffer for
diagnosis.

Precompiled formats are keyed by the complete preamble, preview setup, engine,
and Shuying cache version, then retained below =var/shuying/formats/=.  Batches
waiting for the same missing format share one build.  A batch normally exposes
the cached format in its working directory with a hard link; filesystems that
cannot create that link fall back to a local copy.  If a cached format fails,
Shuying retries the batch once with the complete preamble.  The format is only
discarded when that retry succeeds, distinguishing a stale format from an
ordinary error in the fragment or preamble.

Backends encapsulate process topology and artifact production.  Other engines
or image formats do not add conditionals throughout the scheduler or the Org
adapter.

* External environment

Shuying diagnoses missing tools, but does not silently install a TeX
distribution or modify the system package database.  A TeX installation is
large, platform-managed state and may require administrator access.

** Required programs

The rendering backend requires these commands on =exec-path=:

- =latex= compiles a temporary document to DVI.
- =dvisvgm= converts DVI pages to SVG.

The setup command, package diagnostics, and conditional integration tests also
use =kpsewhich= to locate TeX files.  It is not called while rendering a
preview.

The backend resolves the engine and converter before creating render work or
starting a process.  When either is unavailable, automatic previews remain
quiet and stay eligible for a later preview request; an explicit preview
reports the missing command and, on Windows, points to =M-x shuying-setup=.
Existing cache hits remain displayable without the external toolchain.

Verify them with:

#+begin_src shell
latex --version
dvisvgm --version
kpsewhich preview.sty
#+end_src

** Required TeX packages

Package names below are TeX package names, not necessarily operating-system
package names.

| TeX package | Required file | Purpose |
|-------------+---------------+---------|
| =preview=   | =preview.sty= | Isolate fragments and report their geometry. |
| =amsmath=   | =amsmath.sty= | Standard mathematical environments. |
| =amsfonts=  | =amssymb.sty= | Symbols used by Org's default snippet setup. |

The optional =mylatexformat= package provides =mylatexformat.ltx= and enables
preamble precompilation.  Rendering still works with complete preambles when
that package is unavailable or precompilation fails.

The following are not Shuying runtime requirements, but are a useful baseline
for mathematical notes and custom preambles:

| TeX package | Representative files | Purpose |
|-------------+----------------------+---------|
| =mathtools= | =mathtools.sty=      | Extensions and fixes for =amsmath=. |
| =graphics=  | =graphicx.sty=, =color.sty= | Graphics and basic colors. |
| =xcolor=    | =xcolor.sty=         | Richer color handling. |
| =ulem=      | =ulem.sty=           | Underline and strikeout commands. |

=fontspec= is only needed with XeLaTeX or LuaLaTeX support.  Individual
notes may introduce further dependencies through their preamble; Shuying
should report the missing file from the TeX log rather than guess packages.

Verify the baseline files with:

#+begin_src shell
kpsewhich preview.sty
kpsewhich mylatexformat.ltx
kpsewhich amsmath.sty
kpsewhich amssymb.sty
kpsewhich mathtools.sty
kpsewhich graphicx.sty
kpsewhich xcolor.sty
kpsewhich ulem.sty
#+end_src

** Windows

A per-user Basic MiKTeX installation is recommended because it is small and
does not require administrator access.  A shared MiKTeX installation or
another TeX distribution works as long as the required programs and files are
available.  For MiKTeX, refresh its package database and install the explicit
baseline:

#+begin_src powershell
initexmf --set-config-value=[MPM]AutoInstall=1
miktex packages update-package-database
miktex packages install preview mylatexformat amsmath amsfonts graphics cm-super
miktex packages install mathtools xcolor ulem
miktex fndb refresh
miktex fontmaps configure
#+end_src

On Windows, =M-x shuying-setup= performs this setup explicitly.  It downloads
the current official installer when MiKTeX is absent, verifies its published
SHA-256, verifies its Authenticode signature when one is present, requests a
private unattended install, installs the package baseline above, and verifies
every required program and file.  An unsigned installer is accepted only
after its SHA-256 matches the digest published alongside it on MiKTeX's HTTPS
download page; a present but invalid signature is rejected.  The command is
never called during startup or preview rendering.  Other platforms are
rejected until their setup paths can be tested.

Package installation is idempotent: each package is queried immediately
before installation and an existing package is skipped.  This avoids treating
MiKTeX's nonzero "package is already installed" result as a setup failure,
including when an earlier package installed a later one as a dependency.
Every setup run also configures missing packages to install without a modal
prompt.  Running the command again therefore migrates an existing MiKTeX
installation as well as completing a partial package baseline.

Each invocation uses a private temporary directory.  The directory and the
downloaded installer are removed after success, ordinary failure, or process
startup failure, while the =*Shuying setup*= buffer is retained for diagnosis.
A cancelled Windows installer can hold its downloaded executable briefly, so
both the setup process and Emacs retry cleanup before reporting a leftover.
PowerShell and native-tool output is normalized to UTF-8 before Emacs displays
the log.  Setup does not uninstall MiKTeX or roll back packages after a later
stage fails: some state may have existed before the command, so removing it
would be unsafe.  The operation is repeatable and a later invocation continues
from the installed state.  If Emacs itself is forcibly terminated, its
temporary directory may remain below =var/shuying/setup/= and can be removed
manually.

MiKTeX can install a missing package on demand, but unattended preview jobs
must not wait behind an installation dialog.  The setup command configures
missing-package installation to =Always=; the equivalent manual setting is in
MiKTeX Console.  The explicit baseline includes =cm-super= because Org's
default T1 text encoding needs its scalable outlines when =dvisvgm= converts
commands such as =\text= to SVG.  File and font maps are refreshed after the
baseline so a newly installed outline is visible to the converter immediately.
The setup command refreshes the current Emacs process after the installer
changes =PATH=; restart Emacs if manual installation changes it instead.

** macOS

BasicTeX, the small TeX Live distribution published with MacTeX, is the
recommended macOS setup.  Full MacTeX and other compatible TeX distributions
also work.  Add the required backend and packages to BasicTeX with =tlmgr=:

#+begin_src shell
sudo tlmgr update --self
sudo tlmgr install dvisvgm preview mylatexformat amsmath amsfonts graphics
sudo tlmgr install mathtools xcolor ulem
#+end_src

The DVI-to-SVG path does not need MacTeX's optional Ghostscript extras.  Those
extras are relevant when =dvisvgm= processes PDF or PostScript input.

** GNU/Linux

Distribution-managed TeX Live packages are recommended so the operating
system remains the owner of the installation.  An upstream TeX Live or another
compatible distribution also works.  On Debian and Ubuntu, the corresponding
packages are:

#+begin_src shell
sudo apt install texlive-latex-base texlive-latex-recommended
sudo apt install texlive-plain-generic preview-latex-style dvisvgm
sudo apt install texlive-latex-extra
#+end_src

On Arch Linux, they are:

#+begin_src shell
sudo pacman -S texlive-latex texlive-latexrecommended
sudo pacman -S texlive-latexextra texlive-plaingeneric dvisvgm
#+end_src

Other distributions divide TeX Live differently.  Their package search can
identify the operating-system packages that provide =preview.sty= and the
other files above.  Avoid mixing a system-managed TeX Live with =tlmgr=.

* Testing

Unit tests use fake backends and temporary caches, so the ordinary test suite
does not require TeX.  The same backend contract tests cover immediate and
deferred completion.  Conditional end-to-end tests compile a small set of
fragments with the real =latex= and =dvisvgm= programs and verify the SVG
output, cache reuse, and stale-result rejection.

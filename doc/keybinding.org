* Goals

Keybindings should form a predictable, consistent system throughout Emacs
rather than a collection of unrelated package-specific bindings.

Configure only modes that are actually used.  Do not bind every available
command for completeness; infrequent commands can remain accessible through
~M-x~.

* Resolving binding conflicts

Do not resolve a conflict with a fixed priority order.  Compare the two actions
where the binding applies by considering:

- how often each action is used and how central it is;
- the cost of departing from established conventions; and
- whether either action has an equally convenient alternative binding.

Evil is a strong default, not an absolute priority.  An editing command that
has little use in a read-only buffer costs less to replace than navigation or
search.  Being unavailable alone, however, does not justify reusing its key.

In a structured read-only view, a frequent mode command may replace a text
motion when users normally move by items or sections and those motions remain
convenient.  Apply the override consistently across related views.

When the practical value is otherwise close, prefer established conventions,
then common actions of the major mode, and finally the package's original
bindings.  Treat upstream bindings as a reference.  Choose keys by command
meaning, not by preserving upstream letters.

* Core Evil bindings

Navigable read-only buffers default to normal state.  A separate Evil state may
be justified when the mode's frequent actions would otherwise cause widespread
conflicts with normal-state bindings.

Apply the conflict rules before overriding these bindings:

- ~h/j/k/l~, ~w/b/e~, and ~0/^/$~ move through text.
- ~gg/G~ move to the beginning or end.
- ~C-d/C-u~ and ~C-f/C-b~ scroll.
- ~/~ and ~n/N~ search text and repeat searches.
- ~v/V/C-v~ start visual selection.
- ~f/F/t/T~ and ~;/,~ retain character-find semantics.
- ~m~, the single quote, and the backtick retain mark semantics.
- ~d/c/y~, ~i/a/o~, ~p~, ~r~, ~u~, and ~x~ retain their Evil meanings in
  editable buffers.

Use ~C-=~ and ~C--~ to expand and contract structural selections.

* Common interface semantics

Use these conventions only where the action is meaningful:

- ~q~ quits a temporary or display-oriented view, usually with ~quit-window~.
- In read-only command menus, ~x~ performs an immediate destructive action on
  the semantic object.  Use ~X~ for a clearly related action with broader
  scope.
- ~RET~ invokes the primary action for the item at point.
- In programming buffers, ~K~ describes the symbol at point.
- ~gr~ refreshes the current contents.
- ~M-p~ and ~M-n~ move to the previous or next entry in minibuffer and REPL
  input histories.
- ~C-j~ and ~C-k~ move to the next or previous candidate, revision, chunk, or
  visible section.
- ~M-h~ moves to the parent in hierarchical views.
- In collapsible views, ~za~ toggles the current section; ~zc~/~zo~ hide or
  show it, ~zC~/~zO~ hide or show its child sections, and ~z1~ through ~z4~
  show all sections through the selected level.
- ~TAB~ and ~S-TAB~ move between buttons in document-oriented buffers.

In editable buffers, Evil's ~q~ remains the default.  ~RET~ keeps its Evil
meaning unless a mode below gives it a primary object action.

Closing a buffer, window, tab, or menu dismisses an interface object; it does
not delete the underlying domain data.  These actions therefore use ~q~, not
~d~ or ~x~.

Structured read-only views may use ~y~ as a prefix for copying item
identifiers, paths, or other semantic values.  Keep Visual ~y~ for copying
selected text.

In Xref results, ~j/k~ move by display line and ~C-j/C-k~ move between
references while showing their source.  Use ~[[/]]~ to move between result
groups, ~RET~ to visit a result, and ~gf~ to show its source without leaving
the list.  Use ~i~ to edit results and ~SPC m r~ for query replacement.

Grep and Occur follow the same navigation shape: ~j/k~ move by line,
~C-j/C-k~ move by match, ~RET~ visits, ~gf~ shows the source, ~gr~ refreshes,
and ~i~ enters the result editor.  Grep also uses ~[[/]]~ to move by file.
From a Consult project search, ~M-a E~ exports the results to Grep.

In Magit views, ~RET~ visits the item at point, while ~gf~ previews its
revision without selecting the window used for the preview.

* Edit sessions

An edit session is a temporary editing state with mode-specific finish and
abort actions.  Use those actions instead of treating its buffer as an
ordinary file.

- ~ZZ~, ~:wq~, and ~:x~ apply the edit and leave the session.
- ~ZQ~ and ~:q~ abort the edit and leave the session.

Implement these semantics through command remapping so every Evil entry point
uses the mode's lifecycle.  This convention applies to Org source edit
buffers, Wdired, and the With-Editor buffers used by Magit.

Grep, Occur, and Xref result editors apply each change to the source buffer as
it is made, so they have no truthful discard operation.  Their ~ZZ~, ~:wq~,
~:x~, and native finish command save the source buffers touched during the
session and return to the result view.  ~ZQ~ and ~:q~ refuse to pretend that
the changes can be discarded; undo them first, then finish the session.

* Completion interfaces

While a completion interface is active:

- ~TAB~ incorporates the current candidate or common prefix into the input and
  keeps the interface active when further completion is possible.
- In minibuffer completion, ~RET~ accepts the current candidate or input and
  leaves the completion interface.
- In Corfu, ~RET~ keeps the surrounding mode's action; it does not accept the
  selected completion candidate.

These bindings apply only while completion is active.  The surrounding mode's
bindings resume when completion ends.

* The ~g~ navigation prefix

Use ~g~ as the namespace for navigation-related commands.  Beyond ~gr~, use:

- ~gd~ visits the definition of the symbol at point.
- ~gf~ visits a file or source associated with the current item.
- ~gF~ visits an alternate location for the same item.
- ~g<~ opens recorded output from external commands when available.
- ~gx~ opens the current item's URL in an external program.

Prefer extending Evil's ~g~ prefix with specific sequences over replacing its
sparse keymap.  Check existing sequences such as ~gg~, ~gd~, ~gf~, ~gt~,
~gu~, and ~gv~ before adding a binding.

When overriding an existing sequence, prefer a command whose purpose matches
the sequence's established meaning.  For example, using ~gf~ to visit package
source still means visiting an associated file.  An unrelated override
requires stronger evidence of frequent use.

* Window-local jump history

~C-o~ and ~C-i~ traverse older and newer locations in the selected window.
Each window owns its branch and copies that branch when it is split.  A new
successful navigation after moving backward discards only the newer branch in
that window.

Ordinary buffers use markers, with file and directory data for reopening dead
buffers.  Other location types can register capture, comparison, and visit
functions.  Their values remain opaque to the history.  A visit may complete
asynchronously; the history moves its index only after success, rejects a
second traversal while completion is pending, and skips failed targets.  A
provider can cancel a pending traversal without moving or skipping an entry.

* Leader

Reserve ~SPC~ as the global leader and ~SPC m~ as the major-mode local leader.
Ordinary mode bindings should not replace the global leader.  Temporary
keymaps used by an active prompt may take precedence while the prompt is
active.

Group global commands under prefixes by purpose:

- ~SPC TAB~ operates on tab-based task layouts.
- ~SPC b~ operates on buffers.
- ~SPC f~ operates on files.
- ~SPC g~ goes to destinations associated with the current context.
- ~SPC h~ opens documentation and help.
- ~SPC j~ jumps to locations.
- ~SPC n~ operates on notes.
- ~SPC p~ operates on projects.
- ~SPC q~ exits Emacs or manages its frames.
- ~SPC s~ searches text.
- ~SPC t~ toggles settings or opens a terminal.
- ~SPC w~ operates on windows.

Use ~SPC SPC~ to execute a command by name.
Use ~SPC t d~ to toggle between the configured dark and light themes.
Use ~SPC t i l~ or ~SPC t i d~ to enter fullscreen with the light or dark
theme.  These commands keep an already-fullscreen frame fullscreen.  Use
~SPC t i q~ to leave fullscreen and restore the theme active before entry.
Use ~SPC t t~ to open a terminal in the current directory.  Under the
project map, ~SPC p t~ opens a terminal at the current project root.
Use ~SPC l e~ to enable Eglot for the current language in the current
project, and ~SPC l d~ to disable it.

While Eglot manages a buffer, use ~g D~ for declarations and ~g r~ for
references.  Use ~g a~ to switch between a source and header with clangd.
Use ~SPC l i~ for implementations, ~SPC l t~ for type definitions, and
~SPC l s~ to search workspace symbols.  ~SPC l c~ opens the incoming and
outgoing call hierarchy; ~SPC l T~ opens the supertype and subtype hierarchy.
Use ~SPC l a~ for code actions, ~SPC l f~ to format, ~SPC l o~ to organize
imports, and ~SPC l r~ to rename.  Code actions and formatting also operate
on Visual selections.  Automatic ElDoc feedback stays on one echo-area line.
Use ~K~, or ~SPC l h~, to show complete documentation in a child frame;
documentation never opens a child frame automatically.  The ~SPC l~ editing
entries, ~K~, and the ~g~ bindings disappear when Eglot stops managing the
buffer; ~SPC l e/d~ remain available.

Call and type hierarchies open as trees.  Use ~RET~ to visit a node or toggle
an expansion control, ~g]/g[~ or ~TAB/S-TAB~ to move between controls, and
~gc~ to rebuild the hierarchy with the current node as its root.  Use ~q~ to
close the hierarchy window.

Window commands under ~SPC w~ execute once.  Use ~SPC w SPC~ to enter an
explicit persistent window control map when several operations are needed.
Within that map, recognized keys remain window commands until it is exited;
an unrecognized key exits and retains its ordinary meaning.

Use ~SPC w u~ and ~SPC w r~ to undo and redo window-layout changes in the
current tab.  Each tab keeps its own layout history.  This is distinct from
~SPC TAB u~, which restores a closed tab.

Do not make the ordinary window bindings repeat automatically.  After
~SPC w h~ selects a window, for example, the next ~j~ belongs to the selected
buffer.  Only the explicit control map changes that interpretation.

Use ~q~ consistently for closing buffers, windows, tabs, and similar
temporary objects.

Use an uppercase variant to broaden the scope of its lowercase counterpart
only when the relationship is clear, such as searching one buffer with ~b~ and
a set of buffers with ~B~.

Place mode-specific commands that mutate state or start background work under
~SPC m~ when no stronger direct-key convention applies.  Examples include
installing, pulling, and rebuilding.

These administrative actions are normally less frequent than navigation and
primary actions.  Three sequential keys are acceptable and avoid repurposing
~i~, ~p~, or ~r~ in different buffers.  Promote an action when its
observed frequency justifies a shorter binding.

Package integrations bind their command maps to Evil's ~[localleader]~ event.
Keep the physical ~SPC m~ routing in ~yunge-evil.el~ so changing it does not
require edits throughout the configuration.

Use ~SPC m SPC~ for a mode's primary command dispatcher when it provides one.

Before assigning an uppercase letter, check its Evil meaning.  Keys such as
~B~, ~F~, ~M~, and ~V~ are already bound.

* Org buffers

Org buffers use Evil's general editing model while making common motions,
edits, and text objects aware of Org structure.

Navigation and structural movement:

- On structured lines, ~0~ moves to the content start first and to the physical
  line start when invoked again.  On headings, ~$~ similarly stops before
  trailing tags first and moves past them when invoked again.
- ~C-j/C-k~ move to the next or previous visible heading.
- ~[E/]E~ move to the previous or next Org element.  ~gh/gl~ move to its
  parent or into its contents, and ~gH~ moves to the outermost containing
  heading.
- ~[h/]h~ move to the previous or next heading at the same level.
- ~[l/]l~ move to the previous or next link.
- ~[c/]c~ move to the previous or next source block.
- ~M-h/M-l~ promote or demote the current heading, list item, or table column.
- ~M-j/M-k~ move the current Org structure down or up.
- ~M-H/M-L~ promote or demote an entire subtree.

Editing:

- ~I/A~ enter Insert state at the Org content boundaries.  On headings, ~A~
  stays before trailing tags and fold ellipses.
- ~o/O~ create an Org row or list item when point is in that structure, and
  otherwise retain Evil's ordinary open-line behavior.
- ~C-RET/C-S-RET~ insert a heading or TODO heading after the current Org
  contents and enter Insert state.
- ~d~ retains Evil's operator, register, count, and repeat behavior, then
  repairs affected lists and heading-tag alignment.
- In tables and headings, ~x/X~ use Org's character deletion so columns and
  tags remain aligned.  Elsewhere, and in Visual state, they retain Evil's
  ordinary deletion behavior.
- ~</>~ promote or demote selected headings and indent or outdent selected
  list items.  In other contexts they retain Evil's ordinary shifting.
- In Insert state, ~C-t/C-d~ demote or promote the current heading or list
  item and move the current table column.  Elsewhere they shift the line.

Opening and visibility:

- ~RET~ and ~gf~ open the Org object at point.
- ~<tab>~ and ~za~ cycle local visibility; ~S-TAB~ and ~zA~ cycle the buffer.
- ~zc/zo~ close or open the current fold.  ~zC~ closes the child folds while
  retaining their headings, and ~zO~ opens the complete subtree.

Text objects work with operators and Visual selections.  Lowercase ~i/a~
select inside or around the structure:

- ~ie/ae~ select the Org context at point, whether it is an object or element.
- ~iE/aE~ select the current Org element.
- ~ic/ac~ select the enclosing container.
- ~ih/ah~ select the enclosing subtree.

Use ~SPC n l i~ to insert an Org link and ~SPC n l s~ to store one.
Use ~SPC m t~ to change the current heading's TODO state.

* List buffers

Lists retain Evil movement, search, scrolling, and visual selection.  Commands
that accept a region should operate on the visual selection.

In list buffers that support persistent marks or queued actions, prefer ~m~ for
a generic mark, ~d~ for deferred deletion, ~u~ for unmarking, and ~x~ for
executing queued actions.

Do not extend deferred ~d~ semantics to immediate destructive commands or
interface dismissal.  A command menu can use ~x~ to delete, discard, drop, or
remove its current semantic object while retaining ~d~ for another established
contextual action such as diff.

* Documentation and help buffers

Document-oriented buffers retain Evil movement and text search and use the
common ~q~, ~RET~, ~TAB~, and ~S-TAB~ conventions.

* Document readers

Document readers use one viewer vocabulary whether or not Evil is available.
Do not maintain a second set of Emacs-specific fallback keys.

Shared reader bindings are:

- ~y~ copies the reader's logical text selection in Normal state.  Visual ~y~
  remains ~evil-yank~.
- ~/~ starts a literal document search and ~n/N~ visits the next or previous
  match.
- ~+/-~ zoom in or out, ~=~ resets zoom, and ~W/P~ fit the document width or
  page to the window.
- ~o~ toggles the document outline side window when the active format
  provides one.
- ~gr~ refreshes the rendered view.  A persistent document view does not
  repurpose ~q~ as a window command; Evil retains macro recording there.

Reader view administration remains under the mode-local leader:

- ~SPC m a d~ sets the current book's appearance, ~SPC m a D~ sets the
  format default, and ~SPC m a u~ restores inheritance from that default.
- ~SPC m v~ creates an additional view from the current stable place.
- ~SPC m p~ makes the current view primary.
- In reflowable EPUB views, ~SPC m l +/-~ changes line height,
  ~SPC m l </>~ changes content width, and ~SPC m l =~ resets both.

These commands execute once and do not enter a persistent Reader control map.

In fixed-layout readers, ~J/K~ move to the next or previous page, ~gg/G~ move
to the first or last page, and ~gp~ prompts for a page.  ~C-d/C-u~ scroll by
half a screen in pixels; they must not interpret one rendered page as one
text line.  For the same reason, ~j/k~ scroll by one screen-line height in
pixels.  Page Down and Page Up retain screen-scrolling behavior.  These page
keys stay separate from search repeat keys.  Search-result changes and
~gg/G/gp~ are semantic jumps, so ~C-o/C-i~ can revisit them.  Paging and
ordinary scrolling do not add jump entries.

PDF mouse-wheel input likewise scrolls by bounded device pixels rather than
rendered buffer lines.  Reader does not apply Emacs's progressive text-line
acceleration to the continuous PDF roll.

In paginated reflowable readers, ~J/K~ and ~C-d/C-u~ move to the next or
previous reflowed screen; Page Down and Page Up provide the same commands.
~j/k~ move by one computed content line without the screen-transition
animation.  At a spine-item boundary, line movement continues into the
adjacent linear item.

Mouse-1 selects one character and dragging selects a text range.
Ctrl-Mouse-1 follows a link at the pointer.  ~RET~ remains the portable primary
link action and does not require a GUI modifier.

Outline trees use ~j/k~ and ~gg/G~ for movement, ~TAB~ for folding, and ~q~
to close the side window.  ~RET~ follows an entry and selects its Reader
window.  ~gf~ follows the entry while preserving outline focus, matching
the existing Xref, Grep, and Occur preview convention.  Do not use ~C-RET~
or ~M-RET~ for this distinction: they carry unrelated structural meanings
and are less portable to terminals.

Choosing an outline destination is a semantic jump and participates in
~C-o/C-i~.  Loading an outline may update its hidden buffer, but never opens
a late window or changes focus after the user has moved elsewhere.

* Cross-platform rules

Give every essential function at least one binding that works without Super,
Hyper, function keys, or an operating-system-specific modifier.  Prefer Space,
ASCII letters, ~RET~, and ~TAB~.

Terminals usually cannot distinguish ~TAB~ from ~C-i~.  Preserve ~C-i~ for
jump navigation in Normal state.  Bind ~<tab>~ for GUI navigation and give an
essential action a portable alternative; use ~g]~ for button navigation.  A
completion interface may bind ~TAB~ while it owns input, where jump traversal
is not meaningful.  Do not assume that ~S-RET~ or ~M-RET~ is distinguishable
in every terminal.

~C-u~ scrolls upward in Evil.  Give useful command variants distinct semantic
bindings, such as ~gf~ and ~gF~, instead of relying on a ~C-u~ prefix.

GUI and terminal Emacs may report one physical key as different events.  Bind
~S-TAB~ and ~<backtab>~ together when necessary, but do not write extensive
compatibility code for merely theoretical event combinations.

* Configuration boundaries

Keep Evil's core bindings and the leader in ~yunge-evil.el~.  Put package
integration in the corresponding ~yunge-<feature>.el~ instead of accumulating
all bindings in one file.

Configure an integration only after both Evil and the target feature have
loaded.  Do not load an otherwise unused package just to configure keys, and
do not call ~elpaca-wait~.

* Review

Smoke-test each integration in a real buffer.  Verify its state, core Evil
bindings, primary actions, and GUI or terminal conflicts.  Do not write
exhaustive tests for keymap combinations that cannot occur in normal use.

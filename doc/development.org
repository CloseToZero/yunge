* Setup

Run checks from the repository root with Emacs 31 or newer. Install the
packages pinned in =elpaca-lock.el= before running Emacs tests. Native
checks need a Rust toolchain and Cargo; renderer checks need Node. Some ERT
integrations also require platform tools and report skips when unavailable.

After source changes, =M-x yunge-rebuild= refreshes local autoloads and all
native components. See [[file:setup.org][Setup and recovery]] for prerequisites and recovery.

After changing an autoload declaration, run =M-x yunge-autoload-generate=
and review the tracked =autoloads.sha256= change. The generated loaddefs
cache is under ignored =var/=. The tracked hash describes the generated
declarations, with library names relative to the source directory; the
cache location and generated file name do not affect it. A clean startup
may create the local cache, but does not update the tracked hash.

Elpaca startup is in =yunge-elpaca-bootstrap.el=; its manager and log
keybindings are in =yunge-elpaca.el=. The installer prepares the pinned
checkout and its autoloads in a temporary directory, then moves it into
place. Elpaca's normal build queue handles byte compilation. Bootstrap
tests use a local Git repository and child Emacs processes without network
access or changes to the installed packages.

* Checks

Run all checks:

#+begin_src sh
emacs --batch -Q -L test -l yunge-test-runner
#+end_src

Arguments follow =--=, which separates them from Emacs options:

#+begin_src sh
emacs --batch -Q -L test -l yunge-test-runner -- --suite ert --module theme
emacs --batch -Q -L test -l yunge-test-runner -- --suite static
emacs --batch -Q -L test -l yunge-test-runner -- --suite native --module reader
emacs --batch -Q -L test -l yunge-test-runner -- --suite renderer
#+end_src

=--suite= accepts =all= (default), =ert=, =static=, =native=, or
=renderer=. =--module= works with =ert= and =native=. An ERT module names
a test file family without =yunge-= or =-test.el=: =theme= loads
=yunge-theme-test.el=; =reader= loads =yunge-reader-test.el= and
=yunge-reader-*-test.el=. Native modules are =fangcun=, =mcp=, and
=reader=. Invalid options, empty selections, and failed checks exit nonzero.

=ert= runs Emacs behavior and integration tests; inspect reported skips.
=static= byte-compiles Lisp sources without writing =.elc= files. =native=
runs Cargo tests; =renderer= runs Node syntax and renderer tests. =all=
runs each group once. =M-x yunge-test= starts the full gate in a clean
Emacs process; =(yunge-test 'ert "theme")= starts a focused run from Lisp.

Each run writes Emacs state and XDG caches to a new ignored
=var/test/runs/run-*/= directory while reading pinned package builds from
=var/elpaca/=. Run directories remain for diagnostics and may be removed
after checks finish. Cargo target output stays in its normal project paths.

Graphical smoke is a separate workflow on a machine with the platform
WebView and PDF dependencies. Run regular Emacs, with a display, using the
scripts documented in [[file:../native/yunge-reader/README.org][Reader's native README]]:

#+begin_src sh
emacs -Q --load script/yunge-reader-reflow-epub-smoke.el
emacs -Q --load script/yunge-reader-fixed-epub-smoke.el
emacs -Q --load script/yunge-reader-pdf-smoke.el
#+end_src

=test/yunge-reader-graphical-smoke-test.el= checks the harness in batch; the
scripts above open real graphical Reader sessions and build native release
artifacts.

* Test contracts

Prefer assertions about effects observable by a user or another module:
commands, key resolution, return values, errors, callback completion,
protocol messages, persisted results, and resource cleanup. A test may
control a clock, process, filesystem, or backend boundary to make an
asynchronous case deterministic. Do not test internal implementation details.

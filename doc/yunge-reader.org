#+title: Yunge Reader

Yunge Reader is an extensible Emacs document reader.  PDF is the first full
backend, and EPUB now has a bounded WebView driver.  The core models
ownership, location, selection, and view state without assuming that every
document consists of immutable pages.

* Current PDF slice

Run =M-x yunge-reader-native-setup= once, then visit a =.pdf= file normally.
The PDF adapter is autoloaded through =auto-mode-alist= and turns that file
buffer into a Reader view.  =M-x yunge-reader-pdf-open= remains available as
an explicit entry point.

The current PDF adapter provides:

- verified PDFium installation and a locked Rust helper build;
- open, close, page count, labels, and complete page geometry;
- a centered, continuous, virtualized page roll with bounded image residency;
- replaceable, one-at-a-time background prefetch for the active working set;
- next, previous, direct page, screen, mouse wheel, and ordinary scrolling;
- fit-width, fit-page, and bounded manual zoom;
- canonical bounds and rotated glyph quadrilaterals for local hit testing;
- cross-page drag, polygonal SVG highlights, and bounded exact text copying;
- bounded Unicode literal search, repeat navigation, and glyph-level jumping;
- bounded document outlines with stable internal destinations;
- bounded internal and external page links with local hit testing;
- bounded password prompting with short-lived in-memory credential reuse;
- versioned per-document places with zoom-aware PDF viewport restoration;
- persistent lowercase document marks with exact PDF and EPUB positions;
- window-local back and forward history for semantic Reader jumps;
- immutable render keys, stale-response rejection, and bounded disk cache
  eviction;
- bounded in-memory render, text, and link caches for working pages;
- shared document resources with independent primary and additional views;
- session-bound native handles that cannot alias after a helper restart; and
- graceful, forced, idle, EOF, and Emacs-exit service shutdown paths.

The reader uses one key vocabulary with or without Evil.  Shared keys are
=y= to copy the logical selection, =o= to toggle the outline side window,
=/= to start a search, =n/N= to visit the next or previous match, =gr= to
refresh, =+/-= to zoom, === to reset zoom, and =W/P= to fit width or page.  PDF
views use =J/K= for the next or previous page, =gg/G= for the first or last
page, =gp= for a page prompt, =RET= for a visible link prompt, and Page Down
or Page Up for screen scrolling.  =C-d/C-u= scroll by half a screen in
pixels, while =j/k= scroll by one screen line.  =ma= sets document mark =a=,
and ='a= visits it.  Marks accept lowercase letters =a-z=; uppercase letters
are intentionally unbound.  Mouse-1 clears an existing
text selection, dragging highlights text immediately, and Ctrl-Mouse-1
follows a link when hit.  Pointer motion outside a page image does not extend
the selection until it returns to a page.  Reader handles the initial mouse-down
itself and deactivates any ordinary Emacs region, so buffer text before the
page cannot acquire a second, unrelated region highlight.  Queued pointer
motion is coalesced to its latest position while mouse release retains its
exact endpoint.  Page text is spatially indexed when it arrives, so pointer
hit testing inspects only nearby characters rather than scanning a whole page.
Evil starts Reader buffers in Normal state, leaves Visual =y= as =evil-yank=,
and retains =q= for macro recording.  Reader-local =ESC= and =C-[= bindings
always return Insert or Replace state to Normal, including when an EPUB child
forwards =ESC=.  Main Reader buffers do not bind =q= to window dismissal
because a document view is persistent rather than temporary.
=C-g= and =ESC= clear the logical text selection and hide the active search
highlight without discarding its query or results.  A later =n/N= resumes the
same search and shows its highlight again.  With no Reader highlight to
dismiss, the keys retain their ordinary quit or force-normal behavior.
=M-x yunge-reader-clear-search= ends the search session completely.

Search discovery never blocks the Emacs command loop.  If the next needed
batch is still loading, repeated =n/N= stores only the latest direction rather
than queuing key events.  =C-g= and =ESC= cancel the delayed jump and hide its
paint without ending the search.  Explicit reading movement instead detaches
the old run.  Its one native batch may finish, but it cannot move the view; the
next =n/N= starts in that direction from the new stable reading position.

=M-x yunge-reader-new-view= creates an independent buffer at the current
stable location and zoom while sharing the open document resource.  It refuses
to create a view before the current location is stable, so an incomplete view
cannot silently fall back to page zero or an older saved place.  The existing
primary view is unchanged.  The Additional buffer replaces the active
presentation window deterministically; display the source buffer in another
window first when both views should remain visible.  Run
=M-x yunge-reader-make-primary= to transfer
durable place ownership after saving the current view's stable location.
PDF and EPUB headers identify each buffer as =Primary= or =Additional=.
In Evil Normal state, =SPC m v= creates a view and =SPC m p= makes the
current view primary.  Both commands are one-shot localleader actions.

* Current EPUB slice

Run =M-x yunge-reader-native-setup= once, then visit a local =.epub= file in
graphical Emacs on Windows or macOS.  The adapter is autoloaded through
=auto-mode-alist=; =M-x yunge-reader-epub-open= is the explicit entry point.
Windows reports a missing WebView2 Runtime but never installs it automatically;
macOS uses the system WKWebView framework.

EPUB runs through an Emacs dynamic module.  The module constructs WKWebView
directly through =objc2-web-kit= on macOS and a WebView2 controller directly
through =webview2-com= on Windows.  Each is a real in-process child of the
owning frame.  The backing buffer explains passive duplicate presentations;
selecting one reparents the same loaded child view there.

Consult does not preview unopened PDF or EPUB candidates.  Selecting one clears
any preceding ordinary file preview, and confirmation opens the Reader buffer
once through the normal file action.  This avoids starting either native
backend from transient minibuffer selection.

One shared native publication owns validation, metadata, archive resources,
and its private origin.  Each Reader buffer owns an independent logical view,
locator, native surface, and primary or additional role.  Both platforms use
frame-relative child bounds.  Hiding a buffer hides but retains its loaded
surface.  Displaying it again shows the same DOM and current CFI without
reopening the publication.  Moving a presentation across frames reparents the
same native child and retains its renderer session on both WebView2 and
WKWebView.  The last buffer destroys its retained and obsolete surfaces before
invalidating the publication resource token.

The Lisp adapter represents a surface as exactly one of =detached=,
=creating=, =native-ready=, =opening=, =ready=, or =failed=.  The shared
publication handle and the logical view's lifetime remain independent of this
surface state, so hiding or recreating a child cannot imply that its document
resource or saved logical position has disappeared.

Live EPUB locators contain a bounded CFI, canonical spine href, and optional
finite whole-book fraction.  A fixed-layout locator may additionally contain
a paired, unscaled =x/y= viewport.  Printable Reader places retain the stable
CFI and href plus fixed viewport coordinates; a reflow fraction remains live
progress feedback rather than masquerading as an =x= coordinate.  Ordinary
renderer relocations update only the primary view's durable place.  An
additional view can move independently and becomes a durable-place owner only
through =yunge-reader-make-primary=.

The renderer collapses each visible-range CFI to its start before emitting a
durable locator.  The endpoint depends on window width, font metrics, and
reading style, so retaining the whole range would make an otherwise stable
place change during reflow.  Previously saved range CFIs remain valid restore
inputs.

In a reflowable view, =j/k= move by one computed content line without screen
animation.  =C-d/C-u= and Page Down or Page Up move by reflowed screens, while
=J/K= use semantic page commands that have the same reflowed presentation.
All three scales cross linear spine-item boundaries.  =gg/G= jump to the first
or last linear book location.  The portable commands continue to work after a
mouse click gives the child WebView native focus.  Native and renderer
accelerator events route the bounded Reader vocabulary through the active
Emacs keymaps.  =focus-gained= selects the native surface's owning Emacs
window.  Selecting another Emacs window asks any focused child to return
keyboard focus to its parent, so ordinary Emacs bindings resume without an
extra click.

Native wheel movement remains within the current reflowable spine item until
it reaches a vertical boundary.  Continued input then enters the adjacent
linear item once, while a gesture latch consumes the remaining touchpad or
wheel momentum so one gesture cannot skip chapters.
Pressing =SPC=, =M-m=, or the first =g=, =m=, or ='= in a focused child
returns native focus, then queues the key through Emacs itself.  Leader,
navigation, and mark prefix sequences therefore remain ordinary Emacs input
rather than being copied into the renderer.  The renderer reports native
repeat state without interpreting it; Lisp discards repeats only for these
focus-owning prefix keys.
=o= displays the bounded EPUB 3 navigation or EPUB 2 NCX outline through the
same persistent per-view outline UI used by fixed-layout documents.

EPUB navigation has one active operation and one latest pending intent.  This
keeps a held key moving continuously, while releasing it leaves at most the
latest requested movement instead of a long queue of stale repeat events.  A
new direction or an explicit outline target replaces older pending movement.
Line movement uses the current document's computed line height and completes
without an animation.  Screen movement within a loaded spine item uses
Foliate's bounded 300 ms ease-out animation; crossing into another item may
pause while it loads.  Moving backward at the beginning or forward at the end
is a no-op and leaves the view ready for later navigation.

Each logical EPUB view owns a semantic reading style.  The initial style uses
a 1.0 font scale, 1.6 line height, 720 CSS-pixel maximum content width, and 7%
side padding.  The four values are configurable through
=yunge-reader-epub-default-font-scale=,
=yunge-reader-epub-default-line-height=,
=yunge-reader-epub-default-content-width=, and
=yunge-reader-epub-default-side-padding=.  They are copied when the view is
created, validated at the Emacs, Rust, and renderer boundaries, and applied
before its first navigation.  Hiding and recreating a surface therefore keeps
that view's style, while another view may later diverge independently.
Fixed-layout EPUBs retain their publisher geometry.

Each fixed-layout logical view owns an independent semantic zoom.  It starts
in =fit-page=, also supports =fit-width=, and accepts manual scales from 0.25
through 8.0.  =W/P= select the fit modes, =+/-= switch from the renderer's
current effective scale to manual zoom, and === restores the configurable
=yunge-reader-epub-default-fixed-scale=.  The header distinguishes fit modes
from manual zoom and includes the effective renderer percentage after it is
known.  A resize may update that percentage without replacing the semantic
fit mode.

Fixed-layout =j/k= move the page viewport by 40 screen pixels, =C-d/C-u= and
Page Down or Page Up move by half the child height, and =J/K= turn one logical
publisher page.  Reaching a vertical edge turns a page; moving backward enters
the preceding page at its bottom.  The view reports its viewport in unscaled
page coordinates, restores it only after the spine target loads, and projects
it through the current effective scale.  Manual zoom, fit-mode resize, and
native-surface recreation therefore retain the same page-relative position.
Wheel input scrolls natively inside an overflowing fixed page.  Continued
input at its top or bottom turns one page and consumes the remainder of that
gesture, so touchpad momentum cannot skip through fitting pages or drag the
newly opened page away from its entry position.

The desired zoom belongs to the logical view, not its disposable child
surface.  Hiding and recreating a surface therefore restores the same mode,
while Primary and Additional buffers may diverge independently.  Durable
places retain the fit mode and the last manual scale; renderer feedback alone
does not create a new place.

The visual spine-item scroll bar follows the owning Emacs frame by default.
=yunge-reader-epub-scroll-bar-mode= can instead force it to =hidden= or
=visible=.  Following Emacs reads the frame's actual vertical scroll bar state
whenever the logical view is synchronized, so moving a view between frames or
changing the frame policy does not require reopening the publication.  Hiding
the bar does not disable wheel, keyboard, or pointer scrolling.

Foliate lays out one EPUB spine item at a time, so a visible native bar reports
progress within that item and its thumb can change size at chapter boundaries.
Whole-book progress remains a separate Reader location concern; the chapter
bar is not presented as a publication-wide position.

The same complete style can be changed on a live logical view without
reopening its publication or recreating its native child.  A hidden view keeps
the desired style and supplies it when its next surface opens.  A change made
while the publication is still opening is reconciled after readiness.  The
renderer coalesces updates within one animation frame, and Foliate retains the
visible-range anchor across reflow.  Layout-only anchor movement remains
transient and cannot replace the primary durable place.

Reader's manual scale is the logical view's EPUB font scale and is bounded to
0.5 through 3.0.  The generic zoom-in, zoom-out, and reset commands update the
complete style in place; reset uses =yunge-reader-epub-default-font-scale=.
The header reports the effective font percentage.  A user-requested change
records the new scale with the current stable CFI, while an additional view
cannot replace the primary durable place.  A copied view starts with the source
view's manual scale before its surface opens.  Reflowable EPUB places using a
fit mode are rejected rather than migrated, and fit-width and fit-page remain
unavailable for reflowable documents.

A =publication-ready= locator updates only the logical view.  Readiness means
that an initial target or retained location finished restoring; it is not user
navigation and therefore cannot replace the primary durable place.  Later
screen movement, scrolling, and explicit navigation relocations retain the
normal place-recording rules.  Layout-anchor and text-selection relocations do
not masquerade as reading movement.  Explicit view closure still records its
current stable location.

When an exact retained CFI restores successfully, readiness reports that CFI
instead of replacing it with the renderer's slightly earlier visible-range
measurement.  This prevents repeated surface recreation from walking a
reflowable place backward by one partially visible line.  Href or progression
fallbacks still report the renderer's resolved location.

Chromium remains the only visual EPUB selection layer.  A settled same-spine
range maps its canonical href and collapsed CFI endpoints into Reader's
logical selection.  =y= first snapshots the live DOM range, so copying does
not depend on a preceding =selectionchange= or pointer event.  It then asks
the trusted renderer for that exact =Range.toString()= text in bounded Unicode
batches and publishes it through Reader's normal kill-ring path only after
every batch succeeds.  A stale, cleared, malformed, or oversized range fails
instead of copying unrelated or truncated text.  Native =C-c= remains
available to WebView2.

An ordinary click lets Chromium collapse the DOM range and clears only the
logical text selection; it does not hide a Reader search highlight.  Focused
=ESC= and =C-g= instead resolve through the owning buffer's active Emacs or
Evil maps, dismiss the same Reader transient highlights as their ordinary
buffer bindings, clear the DOM selection through the selection-change hook,
and return focus to that view's Emacs window.

EPUB literal search follows Reader's bounded batch contract.  Each native
request scans at most a configured number of spine items and returns stable
href and CFI ranges with compact context.  Its cursor is a transient match
boundary within one spine; it is never saved as a reading place.  Forward and
backward runs return their nearest match first and accept a stable CFI origin.

Discovery itself creates no annotations.  Reader sends only its current match
back to the renderer, which verifies the same-spine endpoints, navigates via
the coalescing view scheduler, and paints one SVG-overlayer range.  The
logical view retains that desired range across native surface recreation.
Recreation restores only the overlayer and does not override the reading
place already restored for that view.
Chromium selection remains a separate transient layer: ESC and C-g hide both
without ending the search, while n/N restores and moves the search highlight.
Direct wheel, pointer, and touch relocation is reported as user activity, so
it detaches a delayed search jump before the completed batch can replace the
user's new reading position.  The next n/N reanchors at that reported locator.

Reflowable EPUB text layout is available below =SPC m l=.  =+/-= changes line
height in configurable =yunge-reader-epub-line-height-step= increments,
=</>= changes the CSS-pixel content width in configurable
=yunge-reader-epub-content-width-step= increments, and === restores both
defaults.  Renderer bounds clamp repeated commands.  Each update replaces the
complete style of only the current logical view, so hidden surfaces and
Additional views retain independent choices.  The normal primary-only rule
continues to govern durable place recording after reflow.

* Library boundary

The implementation is divided into thirteen pieces:

- =yunge-reader.el= owns drivers, documents, stable positions, logical
  selections, outlines, bounded search state, reader buffers, and zoom state.
- =yunge-reader-transport.el= owns NDJSON framing, handshake queues, request
  identifiers, response callbacks, and session failure.
- =yunge-reader-native.el= owns the PDF helper process, build identity,
  reference counting, cache policy, idle shutdown, and explicit lifecycle
  commands.
- =yunge-reader-setup.el= owns the pinned engine manifest and verified,
  operation-private installation transaction.
- =yunge-reader-pdf.el= maps the format-independent interface onto PDFium,
  virtualizes a continuous page roll, and paints visible selections.
- =yunge-reader-webview-protocol.el= owns the WebView handshake and bounded
  validation of renderer locations, selections, outlines, search, appearance,
  and styles.
- =yunge-reader-webview-view.el= owns logical view records, surface state, and
  the registries that keep them independent from disposable native surfaces.
- =yunge-reader-webview-renderer.el= maps validated EPUB operations onto
  WebView module requests and checks their bounded asynchronous results.
- =yunge-reader-webview-events.el= validates asynchronous renderer events and
  routes them to logical view state and the owning Emacs presentation.
- =yunge-reader-webview-service.el= owns the dynamic-module service, pipe
  transport, shutdown deadline, and stopped-service notification.
- =yunge-reader-webview-surface.el= owns child-surface identifiers, native
  parent geometry, creation, renderer attachment, resize coalescing, and
  asynchronous release barriers.
- =yunge-reader-webview.el= maps persistent logical views onto active Emacs
  presentation windows and owns their buffer-facing integration.
- =yunge-reader-epub.el= maps shared EPUB publications and reflowable
  locations onto the Reader driver interface.

The native WebView service keeps request decoding, stable operation names,
response envelopes, and protocol errors in =src/webview/protocol.rs=.  The
=module/= crate exposes that service to Emacs; the executable remains solely
the PDF helper.  Typed operations coordinate
the publication, renderer, resource, and surface components; unsupported
operations are rejected before they can reach native resources.

=src/webview/surface.rs= owns the validated parent-window adapter, child
WebView construction, bounds, visibility, load state, focus, routed
accelerators, and controller event tokens.  It emits semantic surface events
that the service maps onto protocol events.  It stores no publication handle,
resource token, EPUB locator, or renderer search state, so dropping a native
surface cannot implicitly destroy its persistent logical view or publication.

=src/webview/renderer.rs= owns the browser IPC envelopes, bounded renderer
result validation, semantic renderer-event conversion, and serialization of
every JavaScript command sent to the renderer.  The service owns pending
request identities and decides when to execute those commands.  The renderer
bridge has no child-window handles, publication store, filesystem access, or
EPUB resource-serving authority.

=src/webview/resources.rs= owns embedded renderer assets, both private
origins and their content-security policy, opaque publication tokens, the
token-to-publication store, normalized EPUB paths, and HTTP response
construction.  The direct platform callbacks answer synchronously while ZIP
access remains serialized.  The service retains publication IDs and live-view
close ordering, but cannot inspect the resource store or its archive locks.

PDF selection and search geometry uses one compound SVG path per page and
highlight kind.  Overlapping glyph bounds therefore share one opacity pass
instead of producing darker intersections.  Adjacent axis-aligned glyphs
coalesce into continuous line runs without bridging columns or line breaks.

The core never depends on PDFium, PDF page objects, or PNG.  A driver supplies
a name and file matcher, resource open and close functions, buffer view attach
and detach functions, and a request function.  Open and request completion may
be immediate or asynchronous.  The core guards completions so one driver
mistake cannot complete an operation twice.

The core publishes a canonical opening entry before calling the driver, so
concurrent Reader buffers for one file share the same asynchronous open.  Each
successful buffer then attaches its own format-specific view to the ready
resource.  Closing detaches one view; only the last detach releases the
resource.  A partial attach or failed initial restore removes only that view.

The first attached buffer is the primary view and alone owns ordinary durable
place updates.  If it closes, its final location is recorded before the most
recently active survivor is promoted.  Promotion itself does not immediately
replace the saved location.  Zoom, viewport, selection, search, render caches,
and pending UI work remain buffer-local and independent between views.

A Reader view is owned by its buffer, not by a window.  Removing, replacing,
or deleting a window only hides that view; displaying its buffer attaches the
same view state to a live window again.  Killing the view buffer performs the
actual detach and may release the shared document when no views remain.

One window is the active presentation of that buffer-owned view.  Selecting a
window which displays the buffer makes that window active; hiding it falls
back to another live presentation without changing the view's primary or
additional role.  An explicit window may still be inspected for rendering,
but only the primary view's active presentation can replace the durable place.
For PDF, passive duplicate windows may remain visible, while their scrolling
and resizing cannot change the shared current page, fit geometry, search
anchor, or saved location.

An embedded EPUB surface follows the active presentation.  Moving it between
windows on one frame updates the native child bounds without reopening the
publication.  Moving it across frames uses =view-parent= to reparent the same
WebView2 child HWND or WKWebView host =NSView=, retaining the loaded DOM and
locator.  A passive duplicate window explains that selecting it moves the
surface and points to the explicit Additional-view command.

Opening a document declares one of two layouts:

- =fixed= documents have stable spatial units, normally pages.  PDF, DjVu,
  XPS, and comic archives fit this model.
- =reflow= documents derive line and page breaks from the viewport and
  typography.  EPUB, HTML, and plain text fit this model.

This prevents an EPUB backend from having to imitate permanent PDF pages and
prevents the PDF backend from pretending its glyphs are ordinary Emacs buffer
text.

* Locations, selection, and later annotations

A =yunge-reader-position= contains a document unit, a stable text offset or
driver anchor, and optional unscaled coordinates.  PDF coordinates remain in
the page coordinate system; zoom only changes their screen projection.  A
reflowable backend can instead store a spine item and CFI-like anchor.

The core persists a bounded, most-recently-used place alist through
=savehist=.  Each value is plain printable data containing a format version,
driver name, stable position, zoom mode, and manual scale.  It does not
serialize Lisp structures that may be undefined when =savehist= first loads.
A driver that supports places supplies location and restore functions as a
pair.  EPUB uses that contract without storing an Emacs buffer point, and
later reflowable drivers can do the same.

Reader marks are a separate persistent, document-local namespace.  =m= plus a
lowercase letter stores that document's current stable position, and ='= plus
the same letter restores it.  Multiple logical views of one document share
the marks.  A mark contains only a format version, driver name, and printable
position; it deliberately omits zoom and surface state, so visiting it keeps
the current view's scale and layout.  Each document has at most the 26
lowercase marks, and the most recently modified document sets are bounded by
=yunge-reader-mark-document-limit=.  Uppercase marks are not accepted.

Document appearance has a separate inheritance chain.  Each format reads its
default from =yunge-reader-default-appearances=; both PDF and EPUB default to
=original=.  A document without an explicit override inherits that value, so
=yunge-reader-set-default-appearance= updates every live inheriting document
of the format.  An explicit override survives default changes and is shared by
all logical views of the same document.  Use
=yunge-reader-set-document-appearance= to create one and
=yunge-reader-unset-document-appearance= to restore inheritance.
The same commands are available under =SPC m a=: =d= sets the current book,
=D= sets the format default, and =u= restores inheritance.

Appearance overrides are durable user preferences rather than recency data.
They persist through =savehist= separately from bounded saved places and are
not evicted automatically.  The explicit
=yunge-reader-cleanup-missing-document-state= command removes places,
appearance overrides, and mark sets whose files no longer exist.  It never
runs on a timer, because a temporarily disconnected volume must not silently
lose book preferences or marks.

A restore result of =:deferred= means that the driver accepted a transient
navigation target but cannot yet provide its durable destination.  The core
records the source jump without replacing the current location or saved place;
only a later stable-location event may commit the destination.  Other non-nil
results mean that restoration completed synchronously.

Jump history and the saved place answer different questions.  The saved place
is the most recent successful primary view used when a document is opened
normally.  Additional views cannot replace it until they become primary.
Each jump entry instead owns an immutable snapshot of the file, stable
position, and zoom state at that moment.  Visiting an older entry therefore
does not consult a newer saved place and cannot change the entry underneath a
later traversal.

Reader targets use the same window-local =C-o/C-i= history as ordinary
buffers.  PDF and EPUB =gg/G= commands, PDF =gp=, and successful search result
and outline changes create semantic jumps.  A successful ='a= mark jump also
records its source, including when an EPUB restore completes asynchronously.
=J/K= paging, Page Up or Page Down, =C-d/C-u=, mouse wheel movement, and
ordinary scrolling do not fill the history.

If a target Reader buffer was killed, traversal reopens the document
asynchronously in a hidden buffer.  It replaces the jump window only after the
driver has opened the document and accepted the captured place.  A failed
open or restore leaves the history index, original window, and saved place
unchanged.  If the user changes that window while opening is pending, the late
Reader buffer is closed instead of taking the window away.

Opening treats an old place as pending data.  Place recording remains disabled
through document resource opening, view attachment, the initial refresh, and
restoration.  Only a successful restore permits the current view to replace
the old record.  An unavailable or unbuilt helper, an open, attach, refresh, or
restore failure, an invalid layout, or a rejected restore therefore leaves the
prior place untouched.  In particular, a transient initial PDF page zero
cannot become durable state.

An encrypted PDF first tries a password from Emacs's standard
=password-cache=.  A rejected cached password is removed before prompting.
Yunge Reader permits a bounded number of attempts and remembers a successful
password only in that short-lived memory cache, which expires after 16 seconds
by default.  Passwords never enter document metadata, saved places, or helper
responses.  Cancellation and exhausted attempts release the native lease and
leave an older saved place unchanged.  An asynchronous password failure opens
a minibuffer only while the originating Reader window and view are still
current; a late response cannot interrupt unrelated work.

PDF places store a zero-based page and the canonical page coordinates visible
at the viewport's top left.  Zoom state is restored before building the view;
the coordinates are then projected into the current render size.  A page past
the new document end is clamped to the last page.  If the Reader buffer has no
live window, the PDF adapter retains the position and applies it before the
next visible-page update and before recording any replacement.

An outline is a bounded preorder list of titled entries.  Entries may be
structural headings or carry a format-independent location action with
optional zoom hints; no Lisp object contains a PDFium bookmark or destination
handle.  This lets PDF, EPUB, and later formats share the selection UI and
jump machinery without pretending their source outline formats are identical.

Outline data and loading state belong to the shared document entry.  Concurrent
Reader views coalesce one driver request and reuse the same immutable result.
Each Reader view owns an auxiliary outline buffer with independent point and
fold state.  Closing that view removes its waiter and outline buffer without
cancelling another view's request.

=o= selects a left side window whose fractional width defaults to
=yunge-reader-outline-window-width=.  The tree uses =j/k= and =gg/G= for
movement, =TAB= to fold or expand children, and =q= to close the side window.
=RET= follows a destination and selects a window displaying its Reader view;
=gf= follows the same destination while retaining outline focus.  If a live
view was temporarily hidden, the outline displays its buffer again before
following the destination.  A structural heading
without a destination folds or expands instead.  A rejected target rolls
back view and zoom state and cannot replace the saved place.  PDF XYZ,
fit-page, and fit-width hints map to Reader zoom modes; unsupported fit
variants retain the current zoom.

Outline loading may complete asynchronously.  The side buffer initially
shows a loading status.  Completion updates that buffer even if it is hidden,
but never displays it or changes the selected window.  Reopening it binds the
outline to the Reader view's current live window before a jump.

EPUB outlines reuse Foliate's EPUB 3 navigation and EPUB 2 NCX parsing.  The
renderer flattens that tree into the same preorder contract used by PDF and
marks entries without internal hrefs as structural.  At most 4,096 entries,
256 nesting levels, 1,024 UTF-8 bytes per title, and 3,072 UTF-8 bytes per
href cross the renderer boundary.  Rust independently rejects malformed,
external, or oversized targets before Emacs caches the document-level result.

An EPUB outline href is a one-shot driver anchor, not a durable Reader place.
Following it records the source jump immediately but leaves the view's last
stable locator and saved place unchanged.  Only the subsequent relocation
event, containing a complete CFI, canonical spine href, and optional fraction,
may commit the destination.  This prevents an interrupted or failed deferred
jump from replacing a primary view's last place with a partial href.
If a hidden view's native surface is still being recreated, its logical view
retains only the latest bounded href and dispatches it after publication ready;
a publication error discards that transient target.

EPUB internal links remain inside Foliate and produce an ordinary stable
relocation.  Clicking an external link instead sends its resolved absolute URI
to Emacs as a semantic event; the child never opens a native window itself.
JavaScript, Rust, and Lisp independently require a bounded explicit URI, and
Reader applies =yunge-reader-uri-schemes= before calling =browse-url=.  The
explicit link click may open the URI but cannot update the saved book place.

PDF page links carry format-independent tagged actions, but their source
rectangles remain disposable PDF adapter state.  Local destinations reuse the
same location actions as outlines; external links carry bounded URI actions.
This avoids forcing fixed-page geometry into a future reflowable driver.  The
helper enumerates at most 4,096 links from one page and accepts at most 4,096
UTF-8 bytes for one URI.  Remote-document, embedded-document, Launch, and
unsupported actions remain filtered.

Visible-page prefetch fills a page-indexed link cache and coalesces concurrent
requests, but never activates an action.  =RET= presents links from the
selected Reader window through ordinary completion, with a target page or URI
and stable duplicate suffixes.  Local destinations use guarded live-place
restoration and the window-local =C-o/C-i= history.  Rejected destinations
roll back the view and zoom and cannot replace the saved place.

Only an explicit =RET= choice or Ctrl-Mouse-1 hit may pass an external URI to
=browse-url=.  The default =yunge-reader-uri-schemes= policy allows =https=,
=http=, and =mailto=; other schemes raise a user error unless the user changes
the allowlist.  Opening an external URI neither records a Reader jump nor
updates the document's saved place.

PDF =original= rendering preserves the colors produced by PDFium.  A PDF that
uses =follow-emacs= instead resolves foreground and background colors from the
exact frame presenting the view, then maps every rendered tone between those
two colors.  This deliberately produces a monochrome themed page, including
colored illustrations; switching the document back to =original= restores
its authored colors.

Appearance is part of both the in-memory render key and the native disk-cache
key.  Changing a document appearance or an Emacs theme can therefore retain
the old page only as a temporary fallback while a correctly colored page is
rendered.  It cannot mistake the fallback for a current cache hit.  Selection
and search overlays use the frame's =region= and =isearch= backgrounds only in
=follow-emacs= mode; their existing Reader colors remain unchanged in
=original= mode.

Ctrl-Mouse-1 converts the image coordinate to canonical PDF points and tests
the cached rectangles locally.  When link data is still loading, activation
is allowed only if the original Reader window, buffer, point, scroll state,
selected window, and minibuffer state remain unchanged.  A late completion is
cached without taking over another window.  Mouse-1 and drag events never
follow links.

A logical selection contains two positions and optional resolved text.  Its
painted rectangles are disposable view state, not the source of truth.
Rerendering or evicting an image therefore need not invalidate the text range.
=yunge-reader-copy-selection= copies resolved text or asks the driver for
=selection-text= batches.  Each batch contains directly concatenable text, an
optional stable cursor, and a completion flag.  The core limits both document
units and indexed characters per request, schedules continuation through the
event loop, and publishes text only after every batch succeeds.

Changing or clearing the selection invalidates its copy generation.  A late
batch can neither cache obsolete text nor replace the kill ring, and no later
batches are requested.  Repeating =y= for the same pending selection reuses
the active copy instead of starting a duplicate request.

A buffer-local selection-change hook lets a view adapter synchronize disposable
presentation state after the logical selection changes.  EPUB uses it only to
clear Chromium's DOM selection when Reader state is cleared; a guard prevents
native null-selection events from echoing a second clear request.

A search result uses the same stable endpoints, but its transient highlight is
independent of the copy selection.  Search preview can therefore move and
repaint without changing the text copied from the logical selection.  The
distinction also leaves room for later decoration layers whose durable
records use the same position contract.

For PDF, =unit= is a zero-based page and =offset= is PDFium's zero-based
character index.  A selected range includes both endpoint characters and is
independent of drag direction, including when the drag crosses page slots.
The helper returns Unicode, loose character bounds, and nullable oriented
quadrilaterals in canonical PDF points.  Emacs performs polygon hit testing
locally, stores only the stable endpoints, and asks PDFium to resolve the exact
range text.  Each native batch reads at most 8 pages and 16,384 indexed
characters by default.  A null quadrilateral uses bounds; a malformed non-null
quadrilateral is a protocol error.  Cross-page copy preserves each exact page
fragment and inserts one newline at every page boundary, including when that
boundary separates two protocol batches.

The same boundary can carry later annotations.  Durable annotation data can
store document identity, stable endpoints, quoted text, color, and provenance
outside the renderer.  A PDF backend may additionally write native PDF
annotations, but a PDFium object handle must never be the only durable anchor.
No note-taking or annotation storage is part of the current milestone.

* Continuous roll, zoom, and rendering

Every reader buffer has one of three zoom modes:

- =fit-width= resolves scale from the visible content width;
- =fit-page= resolves scale from both viewport dimensions; and
- =manual= uses an explicit scale between configured bounds.

Opening returns canonical geometry for every page before rasterization.  Emacs
creates one stable buffer slot per page and gives each slot a correctly scaled
space placeholder.  Normal buffer scrolling therefore traverses the complete
document even though most pages have no live image object.

The adapter rasterizes only pages visible in a live window and a configurable
number of neighboring pages.  When a page leaves every window, its display
returns to the equal-size placeholder while its immutable cache path remains
available for reuse.  Navigation moves to an existing slot rather than
rebuilding the buffer, so logical positions and window anchors remain stable.

Window body-size changes schedule one idle viewport update independently of
=window-end=.  Repeated resize notifications replace the pending dimensions
without submitting duplicate work.  In fit modes, the adapter captures the
top-left canonical PDF position from the width actually painted in the page
slot, rerenders for the resized window, and restores that position at the new
scale.  Manual zoom keeps its scale and only recomputes visible-page work.
Closing the view or replacing its window makes a pending resize harmless.

While a new zoom width is rendering, each visible slot keeps the nearest
cached page image and lets Emacs scale it to the target geometry.  This
temporary image does not satisfy the exact native render request.  The adapter
retains at most one fallback per working page and removes it as soon as the
target-width result arrives, so zoom neither blanks the page nor makes image
residency unbounded.

The Rust helper processes requests serially, so each PDF has at most one
background prefetch request in flight.  A viewport change replaces every
unsent task with the new visible and neighboring pages.  Rendering runs before
text and link discovery, while interactive search, selection, and link
requests bypass the background queue.  Explicit helper shutdown also clears
that queue, so background work cannot restart a service the user stopped.

The chosen zoom maps each page to a pixel width between 16 and 8192.  A render
key includes the file's canonical name, size, modification time, page, width,
PDFium API, and native source build ID.  The helper derives the output path
from that 64-character key; an Emacs client cannot ask it to overwrite an
arbitrary path.  Page and width keyed results prevent an obsolete completion
from replacing a different page or scale.

The rendered-page cache starts pruning only after its recognized files exceed
=yunge-reader-cache-max-bytes=, which defaults to 1 GiB.  It then removes the
oldest entries until =yunge-reader-cache-target-bytes=, 768 MiB by default.
A cache hit best-effort updates the file modification time, so eviction
approximates LRU without a second cache index.  The helper operates only on
ordinary files named by exact render keys.  It never removes unknown files,
temporary files, directories, or symbolic links.

In-memory render results, text geometry, and link maps retain only the current
visible and neighboring page set.  Obsolete render widths are discarded too.
Returning to an evicted page can reuse its immutable disk render while text
and links are fetched again.  Stable page slots and canonical page geometry
remain linear in the page count by design; image residency, queued background
work, and page-content caches remain bounded by the viewport working set.

After a click or while dragging, Emacs reuses each visible cached PNG as an
SVG base image and projects that page's part of the logical range over it.
Rotated characters use SVG polygons; older or exceptional geometry uses
rectangles.  The selected window receives an immediate complete redisplay, so
live feedback does not leave stale page fragments.  The source PNG cache
remains independent of ephemeral selection paint.

Document search is cooperatively paged.  One native request scans at most a
configured number of document units and returns a bounded match list plus the
driver's opaque continuation cursor.  Durable reading positions and transient
scan cursors are distinct types.  Emacs stops after the first useful batch and
requests another only for repeat navigation.  An obsolete run cannot publish
results, and each native batch is short enough to let render requests run
between batches.  The search prompt starts empty instead of preselecting the
active query; ordinary minibuffer history still recalls earlier queries.

Repeat navigation is a one-slot intent rather than an input queue.  While a
batch is outstanding, the last =n= or =N= wins, and only one physical search
request remains in flight across obsolete generations.  Reader stays
responsive.  Manual navigation detaches the old run; the next repeat captures
the current stable position and starts a new directional run from there.

The PDF adapter requests text geometry only for ordinary visible prefetch or a
target search page.  It projects the first drawable match character into
display pixels, then adjusts window vertical and horizontal scrolling.  The
match stays correctly anchored across zoom changes because its source of truth
is the PDFium page and character range, not the image or buffer position.

* Native service lifecycle

The helper stays alive while documents are open, retaining parsed PDF state
and avoiding process startup for every page.  It remains owned by Emacs:

- =M-x yunge-reader-native-start= starts it explicitly.
- =M-x yunge-reader-native-stop= requests graceful shutdown, then enforces a
  deadline.  A prefix argument terminates it immediately.
- =M-x yunge-reader-native-restart= replaces it after graceful shutdown.
- =M-x yunge-reader-native-status= reports state, clients, paths, PDFium API,
  helper session, and native build identity.
- =M-x yunge-reader-cache-prune= prunes cached pages while no Reader document
  is open.

PDF documents acquire a service lease at open and release it after their
native =close= response.  Releasing the last lease schedules configurable
idle shutdown.  At the end of that delay, Emacs asks the helper to prune the
cache before shutting it down.  A new lease acquired during pruning prevents
shutdown.  The helper independently refuses pruning while it has an open
document, so Lisp reference counting is not the sole safety boundary.  Setup
refuses to interrupt active reader documents.

The helper also exits when stdin reaches EOF.  This covers forced Emacs exit
where Lisp cannot complete an ordinary request.  =kill-emacs-hook= sends a
best-effort shutdown without delaying editor exit.  The helper does not spawn
grandchildren.

Every startup begins with a =ready= message containing protocol version,
source build ID, PDFium API, and capabilities.  Emacs queues requests until it
validates all four.  Request IDs match asynchronous responses to callbacks.  A
crash fails all outstanding callbacks with a native-session error and permits
at most one automatic restart while a component retains the service.

The PDF helper and WebView module share one transport implementation for NDJSON
framing, handshake queues, request identifiers, response routing, and pending
callback failure.  Each service still owns its handshake validation, error
mapping, events, readiness metadata, and lifetime policy.  A transport session
is bound to its process or module pipe, so stale output cannot consume callbacks
belonging to a replacement session.

Each helper start receives an opaque Emacs-side session identity.  A PDF
document handle pairs that identity with its process-local numeric handle.
Document requests require the same live session, so an old handle cannot alias
a newly opened document whose new helper happens to reuse the same number.
Closing a stale handle releases its service lease without starting or writing
to the replacement helper.  The wire format is documented in
[[file:../native/yunge-reader/README.org][the native protocol document]].

After an unexpected helper exit, the first affected PDF request starts or
joins one document-local reopen.  The native handle belongs to the shared
document, not the buffer that first opened it; recovery takes any password
prompt context from the live view making the request.  Recovery verifies the
canonical file path, size, modification time, and file identity before and
after native open, then publishes the replacement handle atomically.
Concurrent page, text, render, search, link, and outline requests share that
reopen.  A request interrupted by the crash is retried once; another session
loss is reported instead of looping.  View state and saved places remain owned
by Emacs and are not reset.  A changed or closed file is never attached to the
old Reader document.

Password-protected documents reuse the ordinary bounded password and cache
path.  Recovery never raises a password prompt from a background or obsolete
view.  An explicit =yunge-reader-native-stop= ends pending work without
triggering transparent recovery, so the stop command remains authoritative.
The next document operation may start the helper and recover on demand.

* Setup and PDF engine

The tracked manifest pins PDFium =151.0.7881.0= and records a SHA-256 for x64
and arm64 assets on Windows, Linux, and macOS.  Setup performs these steps:

1. Select the asset matching the Emacs operating system and architecture.
2. Download into a private directory below =var/yunge-reader/setup/=.
3. Hash literal archive bytes and require the committed SHA-256.
4. Reject absolute, parent-traversing, drive-qualified, or backslash paths.
5. Extract only the library, version, top-level license, and dependency
   licenses into staging.
6. Parse and verify the four-component upstream version.
7. Atomically publish under =var/yunge-reader/pdfium/7881/=.
8. Build the locked Rust helper and WebView module, then load PDFium in a
   smoke test.

An invalid prior installation is renamed for inspection rather than deleted.
Normal document opening never downloads or compiles dependencies implicitly.

=pdfium-render= is a Rust API wrapper, not a PDF engine implemented in Rust;
the dynamic PDFium library is still required.  Building PDFium from Chromium
source is much larger than an editor setup transaction.  Normal setup uses a
pinned cross-platform binary release.  A maintainer CI recipe can later build
the same PDFium revision from source and publish hashes without changing the
client-side verification model.

The native protocol remains an engine boundary.  A pure-Rust engine can become
another backend after it meets the same rendering, encryption, text geometry,
selection, and annotation conformance tests.

* Reflowable WebView and EPUB driver

The EPUB architecture uses the Rust dynamic module on Windows and macOS.
=M-x yunge-reader-webview-spike= places the empty renderer shell over the
selected Emacs window body.  =M-x yunge-reader-webview-epub-spike= validates a
local EPUB, opens it through that shell, and displays a visible text start in
continuous flow.  A body/text landmark wins, followed by the first table of
contents target and a bounded linear-spine fallback.  A section whose only
media failed to decode is not reported as ready.  The manual command remains
useful as a protocol diagnostic.  Normal =.epub= visits now use the formal
Reader driver, durable places, and shared multi-view ownership.

The renderer embeds a minimal set of modules from Foliate JS revision
=78914aef4466eb960965702401634c2cb348e9b1= under its MIT license.  A
Yunge-owned adapter is the only interface visible to Rust and Emacs; Foliate
objects and DOM ranges do not cross the native protocol boundary.

EPUB 2 NCX navigation documents are exposed alongside EPUB 3 navigation
documents.  The continuous renderer and its inner frame fill the native child
surface rather than inheriting the browser's default element dimensions.

The adapter reduces each Foliate relocation to a Yunge-owned EPUB locator: a
standard EPUB CFI, the canonical spine href, and an optional finite whole-book
fraction.  Both text fields are bounded to 3,072 UTF-8 bytes.  Emacs stores the
latest locator on its owning view rather than in publication-global state.
Destroying the native surface does not replace that locator.

Publication readiness also carries a bounded, flattened table of contents.
The logical view retains it across native surface replacement, while the
Reader document entry coalesces concurrent outline requests and caches one
immutable result for every view.  Point, folding, focus, and the selected
jump target remain view-local.  Destroying a view completes any pending
outline waiter with an error instead of leaving the shared request pending.

Attaching a publication may supply an initial locator.  The renderer first
loads its href, then resolves the exact CFI in that live chapter, with href and
fraction fallbacks; when none resolves to visible content it opens the normal
visible text start.  This avoids waiting on a range anchor while its chapter
frame is still being created.  =M-x yunge-reader-webview-previous-screen= and
=M-x yunge-reader-webview-next-screen= exercise bounded semantic navigation.
They remain unbound protocol diagnostics.  The EPUB driver exposes the same
operations as =J/K=, =C-d/C-u=, and Page Down or Page Up.

The child surface is the preferred reflowable path.  It retains browser-native
text selection, copying, links, accessibility, and CSS layout, and can reflow
the same DOM when its width changes.  An image path would require layout and
rasterization after every width change and would recreate text hit testing and
selection in Lisp.  Image rendering remains appropriate for fixed-layout
documents, but it is not the primary EPUB representation.

Each logical Reader view receives its own numeric native view and WebView
instance.  Emacs sends the frame identifier, its resolved geometry, and the
frame-relative body pixel rectangle.
Window size, state, and buffer changes resynchronize that rectangle.  Only one
bounds request per view may be outstanding; intermediate resize rectangles are
coalesced into the newest value.  Surface creation retains the rectangle
actually sent to the module, so a body-size change before creation completes
is reconciled instead of being mistaken for an applied native resize.  A
formal Reader view survives window replacement: an invisible persistent view
retains its loaded surface and shows it again without reopening.  Windows
and macOS both reparent that same surface when the new presentation belongs to
a different frame.  Killing the buffer destroys the logical view.  A manual
spike remains temporary and is destroyed when its window stops displaying it.

The renderer application and EPUB resource service use separate private
HTTPS-equivalent origins.  Rust exposes only canonical, manifested,
browser-safe resources, and each publication receives a random 128-bit token.
Closing the publication invalidates that token.  Renderer assets are embedded
in the native component and covered by its exact source build ID.

Both direct backends answer resource callbacks synchronously.  In particular,
forwarding a WKURLSchemeTask callback from a worker can leave WebKit waiting
for its system timeout before the first chapter frame loads.  ZIP access
remains serialized on both platforms.  The renderer accepts visible text
before waiting for media and bounds both frame settling and image decoding.
It explicitly announces when its module API is ready, so the native backends
can release queued scripts without polling page-load state.  Lisp retains one
publication-ready deadline so =opening= cannot last indefinitely.

EPUB scripts are rejected by the publication loader, and both reflowable and
fixed-layout Foliate frames omit =allow-scripts=.  A document policy also
denies scripts, objects, child frames, connections, forms, and base URL
changes.  Since those blob documents inherit the renderer application policy,
that outer policy admits only the blob/data presentation sources required for
EPUB styles, images, fonts, and media; it does not admit blob or publication
scripts.  The outer WebView denies permissions, downloads, new windows, and
external navigation.  Renderer IPC accepts only bounded, versioned messages
from the renderer application origin.  The navigation policy separately
admits only renderer-owned =blob:= document URLs, which WKWebView reports for
Foliate's script-disabled chapter frames; those blob frames are never trusted
as IPC senders.

EPUB appearance is logical-view state rather than part of reflow style.  Each
document persists only =original= or =follow-emacs=.  Each surface resolves
that mode against the exact owning Emacs frame and sends a strict palette with
foreground, background, link, selection, and search colors.  Theme changes
refresh every live view that effectively follows Emacs without changing its
saved document preference.  Recreating a surface resolves its palette again,
so moving a logical view between frames cannot retain colors from the old
frame.

A live change uses the independent =view-appearance= operation.  Rejected
updates clear only the applied-surface copy so synchronization can retry.
=original= installs empty appearance styles and therefore adds no Reader
color rules.  For reflowable EPUB, =follow-emacs= composes a style before and
after author CSS while retaining the independent font and line layout rules.
For pre-paginated EPUB, authored page content remains unchanged and only the
outer WebView canvas plus Reader-owned search overlay follows Emacs.

WebView2 forwards =ESC=, =C-g=, =C-d/C-u=, and Page Down or Page Up through
its native accelerator event, while the renderer forwards its bounded
character vocabulary.  On macOS the renderer forwards the complete bounded
reader-key vocabulary through the same accelerator protocol.  Both paths
report only a normalized key and native repeat state.  Emacs resolves these
reading and prefix keys through the owning EPUB buffer's active maps, and
suppresses repeated owning-prefix events there rather than in JavaScript.
=ESC= and =C-g= return native focus to the parent, select the owning Emacs
window, and focus its frame.
Renderer focus events, together with WebView2's native focus notifications,
keep this state synchronized with the owning logical view; an Emacs
window-selection change releases a
focused child when its owner is no longer selected.

=M-x yunge-reader-webview-stop= requests graceful shutdown and then enforces a
deadline; a prefix argument terminates it immediately.  Emacs exit also drops
the module service.  The ordinary PDF helper remains a separate process, so
testing reflow does not interrupt open PDF documents.
Destroying an owned EPUB spike view releases its publication only after native
view destruction completes.  The formal driver additionally waits for every
current or obsolete child surface before closing a shared publication, so no
live renderer can retain an invalid resource token.

No platform dependency is installed automatically.  Windows reports the
detected WebView2 Runtime version or tells the user to install the runtime.
macOS reports its system WebKit version and uses WKWebView without a separate
runtime download.  A future Linux implementation must detect WebKitGTK and
provide an equivalent surface owner.

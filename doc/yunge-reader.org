#+title: Yunge Reader

Yunge Reader opens PDF and EPUB documents in Emacs 31 or newer.  Reading
keys, saved places, outlines, search, and additional views share one
interface; page movement and layout controls follow the document format.

* Start reading

Run =M-x yunge-reader-native-setup= before opening a PDF or EPUB.  Setup
needs a Rust toolchain with Cargo, plus =curl= and =tar= on =PATH=.  It
installs the pinned PDFium library and builds the Reader helper and native
module.  Document opening never downloads or builds dependencies on its own.
The [[file:../native/yunge-reader/README.org][native Reader guide]] covers platform details and graphical
checks.

Visit a local =.pdf= or =.epub= file normally.  The corresponding Reader mode
opens it automatically; =M-x yunge-reader-pdf-open= and
=M-x yunge-reader-epub-open= are explicit entry points.  EPUB needs graphical
Emacs on Windows with WebView2 Runtime, or on macOS with system WKWebView.
The runtime is reported when missing; Reader does not install it.  Consult
does not start Reader backends merely to preview file candidates.

The buffer header identifies its format and whether it is the =Primary= or an
=Additional= view.  A PDF shows a continuous roll of pages.  An EPUB can be
reflowable, with text adapting to its window, or fixed-layout, with authored
page geometry.  Encrypted PDFs prompt for a password when needed and keep a
successful one only in Emacs's short-lived memory cache, never in saved
places.  EPUB scripts are blocked by the publication loader.

* Reading keys

The navigation keys below work in Reader buffers with or without Evil.  When
Evil is active, Reader starts in Normal state and keeps the surface read-only;
Visual =y= remains Evil's ordinary yank.  The mode-local =SPC m= commands
listed below are for Evil Normal state.  Use their =M-x= names without Evil.
After clicking an EPUB's native content, =ESC= or =C-g= returns keyboard focus
to its Emacs window.  Other keys routed from that focused surface form a
smaller set than the full Reader buffer map.

** Shared keys

| Key           | Action                                                     |
|---------------+------------------------------------------------------------|
| =/=           | Search literal document text.                              |
| =n= / =N=     | Next / previous search match.                              |
| =y=           | Copy the logical text selection.                           |
| =o=           | Toggle the document outline.                               |
| =gr=          | Refresh the current view.                                  |
| =+= / =-=     | Zoom in / out using the format's scale.                    |
| ===           | Reset that scale to its format default.                    |
| =ma= / ='a=   | Set / visit document mark =a=; any lowercase =a-z= works.  |
| =C-g= / =ESC= | Dismiss selection and search highlight, keeping the query. |

Main Reader buffers do not use =q= to close a persistent document view.  With
Evil, =q= retains macro recording.  =M-x yunge-reader-clear-search= discards
the query and its results; =C-g= and =ESC= only hide its highlight.

** PDF

| Key                         | Action                                      |
|-----------------------------+---------------------------------------------|
| =j= / =k=                   | Scroll down / up by one screen-line height. |
| =C-d= / =C-u=               | Scroll down / up by half the window height. |
| =Page Down= / =Page Up=     | Scroll down / up by a full window.          |
| =J= / =K=                   | Next / previous PDF page.                   |
| =gg= / =G=                  | First / last page.                          |
| =gp=                        | Prompt for a page.                          |
| =W= / =P=                   | Fit page width / whole page.                |
| =h= / =l=, =Left= / =Right= | Pan an oversized page horizontally.         |
| =zH= / =zL=                 | Pan horizontally by half a window.          |
| =z0= / =z$=                 | Left / right edge of the page.              |
| =RET=                       | Choose a visible link.                      |

Vertical scrolling stays inside a tall page before crossing to its neighbor.
Mouse-1 starts or clears text selection; dragging extends it across pages.
Ctrl-Mouse-1 follows a link under the pointer.  Ordinary wheel scrolling
follows the page roll.

** Reflowable EPUB

| Key                     | Action                                 |
|-------------------------+----------------------------------------|
| =j= / =k=               | Next / previous computed content line. |
| =C-d= / =C-u=           | Next / previous reflowed screen.       |

| =J= / =K=               | Next / previous reflowed screen.       |
| =gg= / =G=              | First / last linear book location.     |

Line and screen movement continue into adjacent linear spine items.  Pointer

** Fixed-layout EPUB

| Key                     | Action                                         |
|-------------------------+------------------------------------------------|
| =j= / =k=               | Move the page viewport down / up by 40 pixels. |
| =C-d= / =C-u=           | Move by half the view height.                  |
| =Page Down= / =Page Up= | Move by half the view height.                  |
| =J= / =K=               | Next / previous publisher page.                |
| =gg= / =G=              | First / last linear book location.             |

At a vertical edge, further movement turns a page.  The wheel scrolls inside
an oversized page and turns a page at its boundary.

** Outline and view commands

In the outline side window, =j/k= and =gg/G= move through entries; =TAB=
folds a branch, and =q= closes the side window.  =RET= follows an entry and
selects its Reader window.  =gf= follows it while leaving outline focus in
place; =gc= returns to the current section.  A heading without a destination
folds or expands rather than navigating.

| Evil Normal key | Command                                  | Action                      |
|-----------------+------------------------------------------+-----------------------------|
| =SPC m v=       | =yunge-reader-new-view=                  | Open an additional view.    |
| =SPC m p=       | =yunge-reader-make-primary=              | Make this view primary.     |
| =SPC m a d=     | =yunge-reader-set-document-appearance=   | Set this book's appearance. |
| =SPC m a D=     | =yunge-reader-set-default-appearance=    | Set its format default.     |
| =SPC m a u=     | =yunge-reader-unset-document-appearance= | Inherit the default.        |

Reflowable EPUB also offers =SPC m l += / =-= for line height, =SPC m l >= /
=<= for content width, and =SPC m l == for resetting both.  The corresponding
commands are =yunge-reader-epub-increase-line-height=,
=yunge-reader-epub-decrease-line-height=,
=yunge-reader-epub-widen-content=,
=yunge-reader-epub-narrow-content=, and
=yunge-reader-epub-reset-text-layout=.

* Reading workflow

** Search, selection, and links

Search is a literal, asynchronous document search.  =/= starts a query, and
=n/N= move among its results.  Reader searches in bounded batches, so a
large document does not block the command loop.  If the next result is still
loading, the latest repeat direction wins.  A manual reading move detaches
that pending jump; the next =n/N= searches from the new stable position.
After one complete wrap, the status changes from =Match N+= to
=Match N/TOTAL= and the discovered cycle can be navigated without another
scan.  Hiding a highlight does not clear its query.

Selection and search highlights are separate.  =y= copies only a logical text
selection and publishes it to the kill ring after all text batches succeed.
A changed or cleared selection makes a late copy result inert.  PDF supports
cross-page drag selection.  EPUB uses the native text surface for selection;
its copy command captures the current range before requesting exact text.

PDF =RET= lists links visible in the selected Reader window; Ctrl-Mouse-1
follows a link at the pointer.  EPUB internal links navigate inside the book.
Explicit external links may call =browse-url= only for schemes in
=yunge-reader-uri-schemes=, initially =https=, =http=, and =mailto=.  An
external link does not change the saved reading place.

** Views, places, marks, and history

Multiple Reader buffers can share one open document.  The first is =Primary=
and alone updates the persistent reading place during ordinary navigation.
=yunge-reader-new-view= creates an =Additional= buffer at the current stable
location and zoom.  It replaces the active window; display the source buffer
in another window first if both should remain visible.  Additional views
can move and zoom independently.  =yunge-reader-make-primary= transfers
persistent-place ownership after saving the current stable location.

The place saves a stable document position and zoom state, not an Emacs buffer
point.  PDF stores a page and unscaled viewport coordinates.  Reflowable EPUB
stores a spine href and CFI; fixed EPUB also retains its unscaled viewport.
Opening restores the last successful primary place.  A failed open or restore
does not replace an older saved place with a temporary starting location.
When the Primary buffer closes, its latest stable place is saved and the most
recently active surviving view becomes Primary.  Promotion alone does not
overwrite the saved place.

Lowercase marks are shared by all views of a document.  A mark saves only a
stable position, so visiting it keeps the current view's zoom and layout.
Document state also holds appearance choices.  It is saved through =savehist=
using a bounded content fingerprint and known path aliases, so a move can
retain state without relying only on the old path.  Run
=M-x yunge-reader-cleanup-missing-document-state= to remove records only
when all known aliases have disappeared; Reader never does this on a timer.

With Evil, =C-o/C-i= traverse window-local semantic jump history.  The
=M-x yunge-jump-history-backward= and
=M-x yunge-jump-history-forward= commands provide the same traversal.
Search results, outline choices, marks, =gg/G=, and PDF =gp= add jumps;
ordinary scrolling, wheel movement, and =J/K= paging do not.  A jump
remembers its own stable position and zoom, independent of the book's newer
saved place.  If its buffer was killed, Reader opens it before replacing the jump window; a
failed restore or a window changed during the wait leaves that window alone.

One Reader buffer may appear in several windows or frames.  Each presentation
has its own observed position and, for EPUB, its own native child surface.
Selecting a presentation adopts its observed location into the active view.
EPUB surfaces stay attached to their native frame; a new frame gets a new
surface and restores the logical view's location.  Removing a window releases
its presentation, while killing the buffer detaches the logical view.  The
last view releases the shared document.

** Appearance, zoom, and layout

=original= preserves the document's authored colors.  =follow-emacs= derives
colors from the frame showing the view.  Each format has a default in
=yunge-reader-default-appearances=; a book can override it or return to
inheritance.  A default change updates live books that still inherit it.
For PDF, =follow-emacs= makes the whole page monochrome between the frame's
foreground and background, including colored illustrations.  For EPUB it
colors the Reader canvas and reflowable text presentation; fixed-layout page
art remains authored.

PDF and fixed-layout EPUB support =fit-width=, =fit-page=, and bounded manual
zoom.  =W/P= choose fit modes, while =+/-= switch to manual scale.  Resizing
recomputes fit scale without changing the selected mode.  Reflowable EPUB
uses =+/-= for font size instead; === restores
=yunge-reader-epub-default-font-scale=.  Fixed EPUB === restores
=yunge-reader-epub-default-fixed-scale=.  PDF manual scale and zoom steps
use =yunge-reader-default-scale= and =yunge-reader-zoom-factor=.

Reflowable EPUB starts from =yunge-reader-epub-default-line-height=,
=yunge-reader-epub-default-content-width=, and
=yunge-reader-epub-default-side-padding=.  The local layout commands change
line height or content width for the current view without reopening the book.
The view keeps its style when hidden or shown in a new native surface.
=yunge-reader-epub-scroll-bar-mode= follows the owning Emacs frame by
default, or forces the chapter scroll bar hidden or visible.  Its thumb
describes the current spine item, not progress through the whole book.

** Services and cache

The native helper serves PDF operations and EPUB publication resources.  It
remains available while documents are open and shuts down after the last
document's idle period.  These commands control or inspect it:

| Command                       | Effect                                                |
|-------------------------------+-------------------------------------------------------|
| =yunge-reader-native-status=  | Report helper state and client count.                 |
| =yunge-reader-native-start=   | Start the helper explicitly.                          |
| =yunge-reader-native-stop=    | Request shutdown; prefix argument forces it.          |
| =yunge-reader-native-restart= | Replace the helper.                                   |
| =yunge-reader-cache-prune=    | Prune PDF page cache when no Reader document is open. |
| =yunge-reader-webview-stop=   | Stop EPUB native surfaces.                            |

PDF keeps rendered images for visible and neighboring pages, while the disk
cache can reuse prior page renders.  =yunge-reader-cache-max-bytes= and
=yunge-reader-cache-target-bytes= control pruning of recognized cache files.
Closing or restarting a helper cannot attach an old document handle to a new
service session.  An unexpected loss can reopen an unchanged document on the
next request; explicit stop ends pending work and does not start recovery
until a new operation asks for it.  Stopping the helper also interrupts EPUB
publication requests; =yunge-reader-webview-stop= controls the separate
native-surface service.  The native guide describes artifact verification,
protocol messages, and graphical checks.

* Extending Reader

** Driver, view, and location contracts

=yunge-reader-register-driver= accepts a symbolic name, an absolute-file
=:match= predicate, =:open=, and =:close= functions.  =:open= receives the
file and a completion callback; it supplies a handle, a properties plist
with =:layout= (=fixed= or =reflow=) and optional =:metadata=, and an error
value.  It may complete immediately or later.  =:close= receives the shared
document.  Concurrent views of the same canonical file share one open and
release it only after the last view detaches.

Optional =:attach= and =:detach= are a pair for buffer-specific setup and
teardown.  Attach receives =(document initial-place)= in the Reader buffer;
detach receives =document= there.  =:location= and =:restore= are another
pair: location receives =(document window)= and returns a stable
=yunge-reader-position=; restore receives =(document position window)= and
returns non-nil once it accepts the target.  Its =unit= identifies a page or
reflowable item, =offset= is a stable text offset or driver anchor, and
=x/y= are optional unscaled coordinates.  A transient renderer range or
native handle is not a persistent location.  A =:deferred= restore leaves
the saved place intact until a stable-location event confirms it.

Drivers may provide these capabilities:

- =:outline= returns =yunge-reader-outline-data= with titled entries and
  optional location actions.  =:outline-index= locates the nearest entry
  for =(document window outline)=.
- =:search= accepts a =yunge-reader-search-request= and returns a bounded
  =yunge-reader-search-batch=.  Its continuation cursor is transient.
- =:selection-text= accepts a =yunge-reader-selection-text-request= and
  returns a =yunge-reader-selection-batch=.  The caller publishes copied
  text only after every batch succeeds.

The asynchronous capabilities receive =(document request complete)=; the
outline request value is nil.  They call =complete= with a result or error
once and may return a child task for the core to adopt.  They can finish
synchronously, so callers must be ready for completion before the capability
returns.

A logical Reader view belongs to its buffer, while each displaying window
owns a presentation.  A driver must keep any resource used by in-flight work
alive until that work releases it.  Detaching one view must not close a
resource still used by another.  EPUB's native surface has one owning frame
for its lifetime; moving a logical view to another frame creates a separate
presentation and restores its stable location.

** Asynchronous tasks and transport

Use a =yunge-reader-task= for work that can outlive its initiating call.  A
completion receives =(value nil)= or =(nil error-data)=, where =error-data=
is an Emacs error value.  It may run during the initiating call or later.
Reader makes the task terminal before invoking completion, so reentrant
finish or cancel attempts cannot notify twice.  A callback error becomes a
warning and does not interrupt response routing.

This standalone example finishes a task from a later Emacs timer event.
Cancelling the returned task first makes the timer's finish inert.

#+begin_src emacs-lisp
(require 'yunge-reader-task)
(let ((task (yunge-reader-task-create
             'preview
             (lambda (value error-data)
               (message "Preview: %S %S" value error-data))
             :timeout 5)))
  (run-at-time 0.1 nil #'yunge-reader-task-finish
               task 'completed "ready" nil)
  task)
#+end_src

=yunge-reader-task-cancel= returns non-nil only for active work.  Its
completion runs synchronously with =yunge-reader-task-cancelled=, and a late
result cannot publish a second outcome.  Cancellation prevents a local
result from taking effect; work already sent to a backend may continue.
An owned child is cancelled with its parent, including one adopted after the
parent finished.  If child cancellation signals, the parent still completes
and Reader warns.  Keep backend resources alive until the backend releases
them; task cancellation alone does not prove native work stopped.

A positive timeout begins at task creation, including handshake wait.  It
completes once with =yunge-reader-task-timed-out= and cancels the active
child.  Custom cancel and timeout functions must make the task terminal and
invoke completion synchronously.  A successful response or service failure
also cancels the timer.

Service requests use newline-delimited JSON.  A validated handshake releases
queued work.  Each response belongs to one request ID and, when supplied,
the same revision.  A wrong revision is a protocol error.  The first late
response for cancelled or timed-out work is discarded; a duplicate remains
invalid.  Losing a service session fails its pending tasks, and output from
an older session cannot complete tasks in its replacement.  See the
[[file:../native/yunge-reader/README.org][native Reader guide]] for wire-level messages and service ownership.

* Verify Reader

Run these checks from the repository root:

#+begin_src sh
emacs --batch -Q -L test -l yunge-test-runner -- --suite ert --module reader
emacs --batch -Q -L test -l yunge-test-runner -- --suite native --module reader
emacs --batch -Q -L test -l yunge-test-runner -- --suite renderer
#+end_src

The [[file:development.org][development guide]] gives the full repository gate and static Lisp
check.  Batch checks cannot establish that graphical PDF pages or EPUB native
surfaces display and respond correctly.  For graphical runs, use the PDF and
EPUB smoke commands in the [[file:../native/yunge-reader/README.org][native Reader guide]].  The scripts generate
their own fixtures and use real PDFium and WebView components.

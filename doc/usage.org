Key sequences below use Evil Normal state unless stated otherwise. ~SPC~ is
Space, ~RET~ is Enter, and ~C-~ means hold Control. ~M-~ means Meta: Alt on
PC keyboards, or Command with Yunge's default macOS settings.

* Edit and save a file

Start Emacs as described in the [[file:../README.org][README]]. Press ~SPC f f~, enter a file
path, and press ~RET~. You can choose an existing file or type a new name;
a new file is created on disk when you first save it.

A buffer holds the text you are editing. A window displays a buffer. Closing
a window leaves its buffer available, and switching buffers leaves unsaved
edits in memory.

** Entering and changing text

Evil starts ordinary editing buffers in Normal state, where letters invoke
commands. Press ~i~ to enter Insert state and type text; press Escape to
return to Normal state. Use ~o~ to insert a line below the current one.

In Normal state, ~w/b~ move by words, ~0/$~ go to line boundaries, and
~gg/G~ go to the beginning or end of the buffer. Combine an operator with
a motion or text object: ~dw~ deletes to the next word, ~ciw~ changes the
word at point, and ~yy~ copies a line. ~p~ puts copied or deleted text after
point. ~v~ starts a character selection and ~V~ selects whole lines; move
to extend the selection, then use ~y~, ~d~, or ~c~ to copy, delete, or change
it. ~C-=~ expands a structural selection and ~C--~ contracts it.

Use ~u~ to undo and ~C-r~ to redo in Normal state. When a prompt or command
has you stuck, ~C-g~ quits it. Escape leaves Insert or Visual state; in a
minibuffer prompt, it changes to Normal state without dismissing the prompt.

For Org files, continue with [[file:org-editing.org][Editing Org documents]].

** Saving and closing

Press ~SPC f s~ or ~C-x C-s~ to write the current buffer to its file.
~C-x s~ offers to save modified file buffers. Save before running a build
or inspecting a Git diff so those tools see your latest edits.

~SPC b b~ chooses another buffer. To return to a recently opened file, use
~SPC f r~. ~SPC b q~ closes the current buffer and asks about unsaved edits;
~SPC w q~ closes only the selected window. ~SPC q q~ exits Emacs, offering
to save modified files.

** Answering prompts

A prompt appears in the minibuffer at the bottom of the frame. Type to narrow
its candidates, use ~C-j/C-k~ to select one, and press ~RET~ to accept.
~TAB~ inserts the candidate or common prefix into the input so you can keep
editing it. ~M-p/M-n~ recall earlier inputs; ~C-g~ cancels.

If you switch the prompt to Normal state, ~j/k~ select candidates and
~C-d/C-u~ move half a page. Use ~i~ to resume typing.

For completion inside a text buffer, use ~C-j/C-k~ to select a Corfu
candidate and ~TAB~ to insert it. ~RET~ keeps the editing mode's action.

* Find your way around a project

Open a file inside the project, then use ~SPC p f~ to choose another project
file without typing its full path. For a Git checkout, Emacs discovers the
root from the repository. Git submodules have their own project roots.

To switch projects, use ~SPC p p~, choose a directory, then choose the action
to perform there, such as finding a file. Opening a project directory in
Dired also remembers it for later selection. Project commands use the
project of the current buffer; switching to an unrelated buffer can change
which project those commands operate on.

** Find text and follow code

Use ~SPC s p~ to search project files. Type a search expression, inspect the
previews, and press ~RET~ on a result to visit it. This needs =rg= or =grep=
on =PATH=. ~SPC s P~ starts the search with the selection or symbol at point.
Use ~SPC s b~ for just the current buffer or ~SPC s B~ for project buffers.

Within a buffer, ~/~ searches forward and ~?~ backward; ~n/N~ repeat the
search. These Evil searches match literal text and expand Pinyin. For
example, ~a.b~ searches for a literal dot; ~:re:a.b~ uses an Evil regexp.
See [[file:yunge-pinyin.org][Pinyin search]] for Chinese text and character-find behavior.

When you know the symbol name, ~SPC j i~ chooses a definition in the current
buffer. With language services enabled, ~gd~ visits the definition at point
and ~g r~ lists references. See [[*Use language services][Use language services]] for setup.

~C-o~ returns to an earlier jump location and ~C-i~ goes forward again.
Each window has its own history. Splitting copies that history, after which
the two windows can diverge. Making a new jump after going backward replaces
that window's newer branch.

** Keep and edit search results

From the project search prompt, press ~M-a E~ to export results to a Grep
buffer. You can keep that list open while visiting matches: ~C-j/C-k~ move
between matches and show the source, ~gf~ previews without leaving the list,
and ~RET~ selects the source. ~[[/]]~ move between files. ~gr~ runs the
search again.

To make a textual change across the results:

1. Press ~i~ in the results buffer to enter its editor.
2. Edit the matching source text using ordinary editing commands.
3. Undo any unwanted edits while still in the results.
4. Use ~ZZ~ or ~C-c C-c~ to save the affected files and finish.

These edits change the source buffers as you type. Finishing saves each
affected buffer in full, including earlier unsaved edits there. ~:q~ and
~ZQ~ report an error and keep this editor open because quitting cannot
roll back changes already applied to source buffers.

Occur and Xref results use the same ~i~ and finish commands. Xref also offers
~SPC m r~ for query replacement. For a symbol rename that should follow
language semantics, use Eglot's rename command instead of text replacement.

* Use language services

Install the server for your language, open a project source file, and press
~SPC l e~. Eglot connects that language group to its server and saves the
choice for this project. Later visits to matching files start it
automatically. Nested projects and submodules need their own enablement.

For C and C++, install clangd and generate =compile_commands.json= with your
project's build system first. Enabling Eglot asks you to choose that file;
it offers databases in the root and build directories, and lets you choose
another location. C and C++ share one server and one enablement choice.

** Inspect and change code

Put point on a symbol and use ~K~ to read its documentation. ~g D~ visits a
declaration, ~SPC l i~ an implementation, and ~SPC l t~ a type definition.
~g a~ switches between a source and header when using clangd. After following
a result, ~C-o~ returns to where you were working.

Use ~SPC l r~ on a symbol, enter the new name, and review the changed buffers
before saving. ~SPC l a~ offers code actions at point or on a Visual
selection. ~SPC l f~ formats the buffer or selection; ~SPC l o~ organizes
imports. The available operations depend on the server and language.

For reported problems, run ~M-x flymake-show-buffer-diagnostics~, then visit
a diagnostic to inspect and fix its source. ~SPC l s~ searches workspace
symbols. ~SPC l c~ opens a call hierarchy and ~SPC l T~ a type hierarchy;
~RET~ follows a node or expands a control, and ~q~ closes the hierarchy.

** Change the setup

For clangd, run ~SPC l e~ again to choose a different compilation database.
A changed choice restarts its active session; the same choice leaves it
running. If the server needs reconnecting, use ~SPC l R~ from a managed
buffer. These commands do not generate the compilation database for you.

~SPC l d~ stops the current server and disables automatic startup for that
project and language group. Disabling C also disables C++, while other
language groups keep their settings.

Files ending in =.h= default to C++. In a C project, run
~M-x yunge-cc-use-c-headers~ to save a C-mode association in the project's
=.dir-locals.el=. Reopen or revert existing header buffers to apply it there.

* Run a build and review the change

Save your edits, then press ~SPC p c~ from a project buffer. Enter the
project's build or test command; Emacs runs it at the project root and puts
output in a compilation buffer. Use ~M-x recompile~ to repeat that command.
When Emacs recognizes file and line references, ~M-x next-error~ visits
them in turn. ~M-x previous-error~ goes backward. Commands that expect
interactive terminal input belong in the project terminal, ~SPC p t~.

To review a Git change:

1. Open ~SPC g g~ for Magit status and use ~gr~ to refresh after external edits.
2. Move through sections with ~C-j/C-k~ and expand a file with ~TAB~ or ~za~.
   ~RET~ visits its source; ~gf~ previews without selecting the source window.
3. On a file heading, press ~s~ to stage that file. Within a diff hunk, ~s~
   stages the hunk. Inspect the staged changes; ~u~ there unstages the file
   or hunk without discarding your working edits.
4. Use ~c c~ to create a commit, write its message, then ~C-c C-c~ or Normal-state
   ~ZZ~ to finish. ~C-c C-k~ or Normal-state ~ZQ~ cancels the message editor.

To stage only some lines of a hunk, start a linewise Visual selection with
~V~, extend it to the changed lines, and press ~s~. Use ~u~ on a selection
in the staged diff to unstage it. The same keys work in a separate diff
buffer opened with ~M-x magit-diff-unstaged~ or ~M-x magit-diff-staged~.
Away from a change section, ~s/u~ prompt for files instead.

Committing records changes locally. Use ~p~ to open the push menu when you
intend to publish them; inspect the selected destination before confirming.
If a Git operation fails, ~g<~ opens its process output. ~q~ leaves status.

* Arrange work and return to it later

** Compare two buffers

Open one file, press ~SPC w v~ to split to its right, then open the second
file in the new window. ~SPC w h/l~ selects the left or right window.
~SPC w s~ splits below instead; ~SPC w j/k~ selects vertically.
~SPC w =~ balances their sizes. ~SPC w q~ closes a window, leaving its
buffer available through ~SPC b b~.

Use ~SPC w u/r~ to undo or redo layout changes in the current tab. For
several resize or selection operations, enter ~SPC w SPC~. Its window
commands repeat until ~SPC~, ~RET~, or ~ESC~ exits; another key exits and
performs its ordinary buffer action.

** Separate tasks with tabs

A tab remembers a window layout; it does not own a separate set of buffers.
Create one with ~SPC TAB n~ and give it a task name. New names must be
nonempty and distinct within the frame; surrounding whitespace is removed.
Set up its windows, then use ~SPC TAB TAB~ to choose another tab. The current
tab is excluded; press ~RET~ without typing to return to the most recent one.
Both tabs can display the same buffer and see the same edits. The current
tab name appears in the mode line when there is more than one tab.

~SPC TAB r~ renames a tab using the same name rules. ~SPC TAB q~ closes it,
and ~SPC TAB u~ restores a closed tab. Closing the tab leaves its buffers open.

** Save a layout across Emacs sessions

First save your file edits with ~C-x s~. Then use ~SPC TAB s~ and give the
workspace a name. A workspace records local file buffers, tabs, and window
layouts; it does not save the text of unsaved edits or running terminal jobs.

After restarting Emacs, use ~SPC TAB l~ and choose that name. Restore reopens
readable files and restores the layout. Non-file and remote buffers are
excluded, so their layout regions may collapse. Existing buffers outside the
saved workspace remain open.

Automatic workspace saving updates =default= every five minutes and before
a normal exit, including ~SPC q r~ to restart. Emacs starts without restoring
a workspace; choose =default= explicitly to recover its layout. Named
workspaces are updated when you save to them again.

** Adjust the display

~SPC t d~ switches between the configured light and dark themes.
~SPC t i l~ enters fullscreen with the light theme; ~SPC t i d~ uses the
dark theme. ~SPC t i q~ leaves fullscreen and restores the previous theme.

* Move, rename, and copy files

Open a directory with ~SPC f d~. In Dired, ~j/k~ move through files, ~RET~
opens one, and ~M-h~ visits the parent directory. ~+~ creates a directory.

For several files, mark each with ~m~; ~u~ removes a mark and ~* u~ clears
marks. Then press ~C~ to copy or ~R~ to move them and choose a destination.
Without marks, those commands operate on the file at point. If another
Dired window is visible, the most recently selected one supplies the suggested
destination. You can edit that path before confirming.

To rename files by editing their names together, press ~i~, change the names,
and use ~ZZ~ to apply the renames. ~ZQ~ cancels without changing the files.
Both return to the ordinary directory listing. To delete files, flag them
with ~d~, review the flags, then use ~x~ to execute the deletion; ~u~ removes
a flag before execution.

Use ~y f~ to copy selected file names, ~y p~ for absolute paths, and ~y P~
for project-relative paths. From an ordinary file buffer, the path commands
are ~SPC f y p~ and ~SPC f y P~.

~SPC m o~ opens selected files in their default applications. ~SPC m e~
opens the directory in the system file manager; ~SPC m r~ reveals selected
local files there. Dragging files into Dired opens a menu for opening,
copying, moving, or linking the group. Choose the action there; keyboard
modifiers do not choose it.

* Finding commands

~SPC~ opens the global leader in Normal and Visual states; ~SPC m~ offers
the current mode's commands. In Insert, Replace, or Emacs state, use ~M-m~
in place of ~SPC~. Pause after a prefix to see available keys. Use ~SPC SPC~
or ~M-x~ when you know a command's name.

When you need to understand the current buffer, use ~SPC h m~ for its mode
help. ~SPC h k~ followed by a key sequence explains the command that key
runs. ~SPC h f~ describes a named command; ~SPC h v~ describes a setting.
~SPC h i~ opens the installed manuals. In a help buffer, ~RET~ follows a
link, ~gh/gl~ move through help history, and ~q~ returns to your work.

During completion or on an item in a buffer, ~M-a~ opens Embark's actions
for that item. This lets you act on a candidate without first visiting it;
for example, ~y~ copies it. The menu shows which actions apply to that target.

#+title: Yunge MCP

Connect a local AI client to Fangcun in a running Yunge Emacs.

* Install and connect

Keep the Emacs instance that owns your notes running while clients use its
tools. Building the bridge requires Cargo; installation also needs a working
=emacsclient= for that Emacs. Run =M-x yunge-mcp-setup= to build and install
the executable, start the Emacs server if needed, and register =yunge= in the
selected clients' user configuration. The first run asks which clients to
register; choose =None= to install without registering any. Successful setup
is remembered, including =None=, so later runs rebuild without asking or
rewriting client configuration. The same choice applies to
=M-x yunge-rebuild=, which updates all of Yunge's build artifacts.

Supported targets are Codex, Claude Code, Gemini CLI, Cursor, and the default
Visual Studio Code profile. Targets can be selected even if their applications
are not installed yet. Build progress and errors appear in =*Yunge MCP build*=.

=M-x yunge-mcp-install= builds and installs without changing client
configuration. The installed executable has a stable path under
=yunge-mcp/bin/= in =yunge-var-directory= (by default =var/=); the platform may add an executable
suffix. The [[file:../native/yunge-mcp/README.org][native bridge guide]] explains the runtime manifest and protocol.

* Register or reconnect a client

After installing the bridge, use =M-x yunge-mcp-register-clients= to add
another client or replace its =yunge= entry without rebuilding. Select one or
more clients, separated by commas. Registration does not require the client
application to be installed, and registering one client does not remove entries
from others.

Choosing =None= records that no registration is needed; it does not remove
existing entries. A failed registration is not saved as a completed choice.

For JSON configuration files, registration replaces the =yunge= entry and
preserves other settings, though formatting may change. An existing file must
contain a JSON object; an empty file, malformed JSON, or a non-object server
section is rejected. Correct the file named in the error and run registration
again.

Codex uses TOML. Its registration runs the installed Yunge MCP executable to
read the configuration and replace =mcp_servers.yunge=, preserving other
settings. Run =M-x yunge-mcp-install= first if the executable is missing or
does not support configuration editing. =yunge-mcp-setup= already builds and
installs it before registration. Invalid TOML or a non-table =mcp_servers=
value is rejected without changing the file.

If writing a configuration fails, its previous contents remain intact.
Registration processes selected clients in order: if one fails,
earlier updates remain and later clients are not changed. After fixing the
error, run registration again; the bridge does not need rebuilding.

If a client cannot reach Emacs, check that the configured Emacs server is
running. After changing the Emacs installation or server connection, run
=M-x yunge-mcp-install= to refresh the connection settings. Use the same
command when the bridge reports that its helper is outdated.

For changes to registration or tool dispatch, see [[file:yunge-mcp-development.org][Yunge MCP development]].

* Find and edit a note

Start with =fangcun_list_yiyus= to find your note roots. Search for a title,
alias, tag, root, or relative filename with =fangcun_search_nodes=. Search
ignores case, and every whitespace-separated term must match. To search for
text inside a note, use the client's filesystem search within the returned
roots.

Pass a result's ID to =fangcun_locate_node=. It returns an absolute filename
and the saved node's line range: the whole file for a file node, or the subtree
for a heading. Use the client's filesystem tools to read that range and make
edits. Locate again after edits that might move the node. For related notes,
=fangcun_list_backlinks= finds nodes that link to this ID across all roots.

Check =modifiedInEmacs= before editing externally. If it is true, the Emacs
buffer contains unsaved changes that the disk location and filesystem reads
do not include. Save those changes in Emacs first, or reconcile the two
versions before continuing. MCP location queries leave the buffer untouched.

Use ordinary Org links in note text: =[[id:NODE-ID][description]]= links to a
node, and =[[id:NODE-ID::target][description]]= searches within it.
Saved external edits reach the index when Fangcun's optional watcher notices
them and Emacs processes the events. If monitoring is unavailable or search
results look stale, run =M-x fangcun-db-sync= in Emacs. Search and backlinks
use the index; locating a node rereads its saved file. See the
[[file:fangcun.org][Fangcun guide]] for index recovery and checking links.

* Create a node

Use =fangcun_create_file_node= for a new note. Supply a configured =yiyu= ID,
a portable =.org= path relative to that root, and an optional =title=. Missing
parent directories are created. The tool assigns a file-level Org ID, saves,
and indexes the file before returning the node. Add content with filesystem
tools afterward. An existing file or a buffer already visiting that path
prevents creation.

Use =fangcun_create_heading_node= to give an existing heading its own ID.
For example, for a heading named =Lemma= below =Algebra=, pass:

#+begin_example
{"yiyu":"personal","file":"math.org","headingPath":["Algebra","Lemma"]}
#+end_example

Heading titles must match exactly, excluding TODO keywords, priorities, and
tags. Missing or ambiguous paths fail; an existing local ID is kept. The tool
saves and indexes the file. It refuses unsaved Emacs changes, and refreshes an
unmodified visiting buffer if the file has changed on disk.

A creation error can occur after the file has been saved, for example when
indexing finds a duplicate ID. If the error reports a saved file, inspect it,
fix the reported problem, and run =M-x fangcun-db-sync=. Keep its existing ID;
do not retry creation of the same file.

If you cancel a creation request or lose the client connection, inspect the
target file before trying again. Emacs may already have saved it even though
the client did not receive a result. Keep any assigned ID and synchronize the
index with =M-x fangcun-db-sync= if needed.

* Tool results and pagination

| Tool | Arguments | Result |
|------+-----------+--------|
| =fangcun_list_yiyus= | none | Array of configured =id=, =name=, absolute =root= |
| =fangcun_search_nodes= | =query=; optional =pageSize=, =cursor= | Ranked =nodes= with =matchedFields=; optional =nextCursor= |
| =fangcun_locate_node= | =id= | =node= and saved-file =location= |
| =fangcun_list_backlinks= | =id=; optional =pageSize=, =cursor= | =target=, unique source =backlinks=; optional =nextCursor= |
| =fangcun_create_file_node= | =yiyu=, =file=; optional =title= | Saved, indexed file node |
| =fangcun_create_heading_node= | =yiyu=, =file=, =headingPath= | Saved, indexed heading node |

A node result contains =id=, =title=, =aliases=, =tags=, =yiyu=, =yiyuName=,
and its yiyu-relative =file=. Each search entry contains a =node= and the
metadata fields matched by the query in =matchedFields=.

A location contains =absoluteFile=, =kind= (=file= or =heading=), inclusive
one-based =startLine= and =endLine=, =outlinePath=, and =modifiedInEmacs=.
The accompanying node metadata comes from the index and can lag behind the
saved text used for its location.

Each backlink has a =source= node, =occurrenceCount=, and =firstPosition=.
The position is a one-based Emacs character position in the indexed source
file. Repeated links in one source count as one paged result.

For paged tools, =pageSize= defaults to 20 and must be 1–100. If =nextCursor=
is present, pass it as =cursor= with the same query or target ID. Treat the
cursor as opaque; absence of =nextCursor= means the final page.

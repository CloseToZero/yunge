Search Chinese text with Latin letters in Yunge. Ordinary text remains a
literal match, while valid Pinyin can also match Han characters. You can use
full syllables, an unfinished final syllable, or initials.

* Search text

In Evil, press =/= to search forward or =?= to search backward, then type a
query. For example:

| Query       | Can match  | Meaning                                |
|-------------+------------+----------------------------------------|
| =baoliu=    | =保留=     | Full syllables                         |
| =baol=      | =保留=     | Incomplete final syllable              |
| =bl=        | =保留=     | Initials only                          |
| =xi'an=     | =西安=     | Apostrophe fixes the syllable boundary |
| =lvse=      | =绿色=     | =v= stands for =ü=                     |
| =:py:beijx= | =背景像素= | Mix full syllables and initials        |

Without =:py:=, a query must use full syllables (with at most an incomplete
last one) *or* initials throughout. Thus =beijx= does not expand to =背景像素=
by default, but =:py:beijx= does. The prefix selects the more permissive
grammar for that query. After the prefix is removed, =beijx= still matches
literally. The compiler does not guess whether Latin text is English.

Evil's =/= and =?= treat punctuation as literal text, so =a.b= does not mean
a regexp wildcard. Start with =:re:= when you want an ordinary Evil regexp.

Uppercase Pinyin can still match Han characters. Evil retains its smart-case
behavior for Latin text: an uppercase query does not also match lowercase
literal letters when case-sensitive search applies.

* Other search entries

- =SPC j j= starts an Avy jump to visible text. Type the same Pinyin queries,
  including =:py:= for mixed forms. Avy does not interpret =:re:= as a regexp
  prefix.
- Orderless completion accepts Pinyin in ordinary components. For example,
  =bl= can match a candidate containing =保留=; =:py:beijx= selects mixed
  grammar. Use =:re:= for an Orderless regexp component or ~=bl~ for literal
  matching. File-path completion uses partial completion instead of this
  Orderless matching style.
- Evil's =f=, =F=, =t=, and =T= also expand a *lowercase ASCII letter* to
  Chinese characters with that Pinyin initial. The letter itself remains a
  match. Uppercase character-find prompts are not expanded this way.

* Input and limits

Tone marks are accepted: =lǜse= and =lvse= both match =绿色=. Use =ü= or =v=
for that vowel; the =u:= spelling is not accepted in search queries. Tone numbers
are literal digits: =ni3= can match =你3= but does not match =你=. Apostrophes force
boundaries; =xi'an= matches =西安= but not =先安=.

A query always keeps its literal match. Pinyin expansion uses frequency-ranked
characters and a complexity budget. The default
=yunge-pinyin-max-frequency-level= is 4; level 5 admits rarer candidates but
still obeys the budget. Broad queries may receive a narrower expansion or stay
literal so interactive searches remain responsive. Set
=yunge-pinyin-regexp-budget= to change the maximum expansion cost. Set
=yunge-pinyin-query-grammar= to =permissive= to make mixed forms the default;
=:py:= always requests that grammar explicitly.

* Use from Lisp

Require =yunge-pinyin= and pass a compiled regexp to an Emacs regexp consumer:

#+begin_src emacs-lisp
(require 'yunge-pinyin)

(string-match-p (yunge-pinyin-query-regexp "baoliu") "保留")
(string-match-p (yunge-pinyin-query-regexp ":py:beijx") "背景像素")
#+end_src

Both expressions return =0=. =yunge-pinyin-regexp= accepts an optional
=structured= or =permissive= grammar argument for text without query syntax;
=yunge-pinyin-query-regexp= interprets the initial =:py:= prefix.
=M-x yunge-pinyin-clear-cache= discards compiled results without unloading
the Pinyin data.

* Update the data

The runtime index =lisp/yunge-pinyin-data.el= is committed, so searching needs
no download or generation. It was generated from Unicode Unihan 17.0.0. To
update it, obtain that version's =Unihan_Readings.txt=,
=Unihan_DictionaryLikeData.txt=, and =Unihan_OtherMappings.txt= from the
[[https://www.unicode.org/Public/17.0.0/ucd/Unihan.zip][official Unihan archive]], then run from the repository root:

#+begin_src shell
emacs --batch -Q --script script/generate-yunge-pinyin-data.el \
  /path/to/Unihan_Readings.txt \
  /path/to/Unihan_DictionaryLikeData.txt \
  /path/to/Unihan_OtherMappings.txt \
  lisp/yunge-pinyin-data.el
#+end_src

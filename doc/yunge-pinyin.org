* Scope

=yunge-pinyin= is a Pinyin query compiler shared by Evil search, Orderless,
Avy, and any other Emacs code that accepts a regexp.

Evil's ~f/F/t/T~ character-find commands also compile a lowercase ASCII
letter as a one-letter Pinyin query.  The literal letter remains a candidate,
while Han characters with that initial become additional candidates.  This
uses the same bounded data and cache as the longer search commands.

The public entry points are:

- =yunge-pinyin-normalize= for tone and ü normalization;
- =yunge-pinyin-segmentations= for ranked syllable segmentation;
- =yunge-pinyin-regexp= for a literal-or-Pinyin search regexp;
- =yunge-pinyin-query-regexp= for shared =:py:= query-prefix handling;
- =yunge-pinyin-clear-cache= for clearing generated character classes.

The regexp compiler uses a bounded syllable DAG.  Its default structured
grammar accepts either full syllables with an optional incomplete final
syllable, or a query made entirely of initials.  For example, =baoliu=,
=baol=, and =bl= all match the same Pinyin phrase.  Apostrophes force syllable
boundaries.

The explicit =:py:= prefix selects a permissive grammar which may mix full
syllables and initials inside one query.  The same syntax is accepted by Evil
search and Avy; Orderless exposes it through =orderless-kwd=, for example
=:py:beijx=.  Set =yunge-pinyin-query-grammar= to =permissive= to make that
grammar the default instead.

This distinction is purely grammatical: the compiler does not try to detect
whether input is English.  A complexity budget based on the expanded
character sets and abbreviated initials prevents broad queries from producing
an expensive regexp.  A query always remains searchable literally.

The compiler normally stops at frequency level 4.  This keeps ordinary
queries focused on modern-use characters instead of expanding them with the
rare Unihan tail.  Set =yunge-pinyin-max-frequency-level= to 5 when exhaustive
coverage is more important than interactive search speed.

Compiled character classes, cumulative character counts, and a bounded set of
complete query regexps are cached in memory.  =yunge-pinyin-clear-cache=
clears those caches without unloading the generated data.

* Data

The committed =lisp/yunge-pinyin-data.el= is the runtime Pinyin-to-Hanzi index.
It is generated from Unicode Unihan 17.0.0 and loaded lazily on the first
Pinyin query.  Users do not need to download or generate anything during
installation or startup.

The generated data uses these Unihan properties:

- =kMandarin=, =kHanyuPinyin=, and =kTGHZ2013= for readings;
- =kHanyuPinlu=, =kGradeLevel=, and =kTGH= for five frequency buckets.

The data is licensed under Unicode-3.0; see
=LICENSES/Unicode-3.0.txt=.  The compiler and generator are MIT-licensed
original code.

* Regenerating the data

Only maintainers updating the Unicode version need the original files.
Download the official archive from:

https://www.unicode.org/Public/17.0.0/ucd/Unihan.zip

Extract these files from the archive:

- =Unihan_Readings.txt=
- =Unihan_DictionaryLikeData.txt=
- =Unihan_OtherMappings.txt=

Then run, from the repository root:

#+begin_src shell
emacs --batch -Q --script script/generate-yunge-pinyin-data.el \
  /path/to/Unihan_Readings.txt \
  /path/to/Unihan_DictionaryLikeData.txt \
  /path/to/Unihan_OtherMappings.txt \
  lisp/yunge-pinyin-data.el
#+end_src

The large original Unihan text files are deliberately not committed.  The
generated =.el= file is committed so a clean checkout works without a package
build step or network access.

#+title: Yunge Reader native protocol

The helper is a child process owned by Emacs.  Emacs and the helper exchange
UTF-8 newline-delimited JSON over stdin and stdout.  Standard output is
reserved for protocol messages; diagnostics use standard error.

* Environment

=YUNGE_READER_PDFIUM= is the absolute path of the pinned PDFium dynamic
library.  =YUNGE_READER_CACHE= is the absolute render cache directory.  PDFium
is loaded lazily by =pdfium-info= or =open=, so lifecycle diagnostics can still
run when the engine is unavailable.

* Handshake

The helper writes one message immediately after startup:

#+begin_src json
{"kind":"ready","protocol":1,"build-id":"HASH",
 "pdfium-api":"7881",
 "capabilities":["cache-maintenance","lifecycle","pdf-links",
                 "pdf-outline","pdf-render","pdf-search","pdf-text"]}
#+end_src

Emacs requires the protocol, build ID, PDFium API, and all capabilities to
match.  The build ID hashes the Cargo manifest and lock, build script, PDFium
manifest, Rust sources, and bundled renderer sources.

* Requests and responses

Every request has a positive integer =id=, an =op=, and an optional =params=
object.  Exactly one response uses the same ID.  Operation parameter objects
reject unknown fields.

#+begin_src json
{"id":1,"op":"ping"}
{"id":1,"ok":true,
 "result":{"protocol":1,"backend":"pdfium",
           "capabilities":["cache-maintenance","lifecycle","pdf-links",
                           "pdf-outline","pdf-render","pdf-search",
                           "pdf-text"]}}
#+end_src

Failures have a stable code and diagnostic message:

#+begin_src json
{"id":2,"ok":false,
 "error":{"code":"unknown-document",
          "message":"unknown document handle: 99"}}
#+end_src

* Cache maintenance

=cache-prune= accepts a positive =max-bytes= and a nonnegative
=target-bytes= no greater than the maximum.  When recognized cached pages
exceed the maximum, the helper removes the oldest entries until their total
is at or below the target.  A successful =render-page= cache hit updates the
entry's modification time, making this a filesystem-backed LRU
approximation.

#+begin_src json
{"id":3,"op":"cache-prune",
 "params":{"max-bytes":1073741824,"target-bytes":805306368}}
{"id":3,"ok":true,
 "result":{"scanned":120,"before-bytes":1200000000,
           "after-bytes":800000000,"removed-files":40,
           "removed-bytes":400000000,"failed-files":0,
           "over-budget":false}}
#+end_src

The operation is permitted only while the helper has no open documents.
It recognizes only ordinary files directly under =YUNGE_READER_CACHE= whose
names are exactly 64 lowercase hexadecimal characters followed by =.png=.
Unknown files, temporary files, directories, and symbolic links are ignored
and never removed.  The configured cache root itself must be an absolute,
real directory rather than a symbolic link.  Individual removal failures do
not stop the scan; =failed-files= and =over-budget= let Emacs report an
incomplete cleanup.

* Windows WebView service

Starting the same executable with =--webview= selects a separate NDJSON
service.  It does not load PDFium or share document handles with the ordinary
service.  Its handshake reports the installed WebView2 Runtime without
installing or downloading it:

#+begin_src json
{"available":true,"build-id":"HASH",
 "capabilities":["publication-close","publication-info","publication-open",
                 "publication-resources","view-bounds",
                 "view-clear-selection","view-create",
                 "view-destroy","view-events","view-focus",
                 "view-focus-parent","view-info","view-navigate",
                 "view-open-publication","view-search",
                 "view-search-result",
                 "view-selection-text",
                 "view-scroll-bars","view-status","view-style",
                  "view-visible"],
 "accelerators":["+","-","=","<escape>","<next>","<prior>",
                 "C-d","C-g","C-u","J","K","M-m","SPC","j","k","y"],
 "engine":"webview2","kind":"webview-ready","platform":"windows",
 "protocol":1,"version":"151.0.4129.86"}
#+end_src

When the runtime is missing, =available= is false and =message= tells the user
which environment to install.  The process remains responsive so
=view-info= and =shutdown= still work.

=publication-open= accepts an absolute local EPUB path.  Rust validates and
owns the ZIP container, returns the package path and minimal OPF metadata, and
assigns a process-local publication ID.  It does not expose the filesystem
path to JavaScript.  =publication-info= repeats the bounded metadata and
resource statistics, while =publication-close= releases the ZIP handle.  Both
open and info also return a private =resource-root= capability URL.

#+begin_src json
{"id":1,"op":"publication-open",
 "params":{"path":"D:/books/example.epub"}}
{"id":1,"ok":true,
 "result":{"publication":1,
           "resource-root":"yunge-reader-book://TOKEN/",...}}
#+end_src

Every child WebView registers =yunge-reader-book= as an asynchronous HTTPS
custom protocol.  A request below =resource-root= reads only a normalized ZIP
entry belonging to that random 128-bit publication token.  Closing the
publication invalidates the token.  At most eight resource requests may be
active, each expanded response is limited to 128 MiB, and ZIP access remains
serialized per process.

Only =GET= and =HEAD= are accepted.  Query strings, absolute paths, encoded
separators, dot components, missing entries, resources absent from the OPF
manifest, and media types outside the browser allowlist receive explicit HTTP
errors.  Package and =META-INF= XML remain available for the EPUB loader.
JavaScript media types are deliberately outside the allowlist.  Responses deny
sniffing and caching, allow token-bearing cross-origin reads, and apply a CSP
that blocks scripts, objects, frames, forms, connections, and external
subresources.

The built-in child page opens the validated publication through its private
resource origin.  Its bundled, script-disabled Foliate renderer provides CSS
layout, native text selection, links, relocation events, and semantic screen
navigation without exposing the local EPUB path.

=view-open-publication= attaches an open publication to a child view.  It
accepts an optional stable locator, a complete semantic reading style, and a
required resolved scroll bar policy:

#+begin_src json
{"id":2,"op":"view-open-publication",
 "params":{"view":1,"publication":1,
           "scroll-bars":false,
           "style":{"font-scale":1.0,"line-height":1.6,
                    "content-width":720,"side-padding":7.0}}}
#+end_src

Font scale is bounded to 0.5--3.0, line height to 1.0--3.0, content width to
320--1,600 CSS pixels, and side padding to 0--20 percent.  Omission selects
the same defaults shown above.  Unknown or partial style objects are rejected;
arbitrary CSS, fonts, and colors never cross the protocol boundary.  The
renderer maps these fields to reflowable layout before its first navigation
and leaves fixed-layout publication geometry unchanged.

=view-style= accepts the same complete style object for an attached view.
The renderer coalesces updates requested within one animation frame and lets
Foliate retain its current visible-range anchor while the document reflows.
Changing style does not reopen the publication, recreate the child surface,
or emit a durable location for layout-only movement.  A renderer-side failure
is reported as a bounded =style-error= event.

=view-scroll-bars= changes only the visual bar of an attached view.  The
boolean =visible= field is required, scrolling remains enabled in either
state, and a renderer-side failure is reported as a bounded
=scroll-bars-error= event.

#+begin_src json
{"id":3,"op":"view-scroll-bars",
 "params":{"view":1,"visible":false}}
#+end_src

Successful publication readiness is an unsolicited event containing the
first complete locator and a flattened EPUB 3 nav or EPUB 2 NCX outline:

#+begin_src json
{"kind":"event","event":"publication-ready","view":1,
 "location":{"cfi":"epubcfi(/6/4!/4/2)",
             "href":"OPS/chapter.xhtml","fraction":0.1},
 "outline":{"items":[
   {"title":"Part One","depth":0},
   {"title":"Chapter 1","depth":1,
    "href":"OPS/chapter.xhtml#start"}],
   "truncated":false}}
#+end_src

The renderer emits at most 4,096 outline items and 256 nesting levels.  A
title is at most 1,024 UTF-8 bytes, an internal href is at most 3,072 bytes,
and aggregate title and href text is at most 384 KiB.  The Rust boundary
independently validates every item and limits the complete renderer message
to 1 MiB.  Structural items omit =href=.  Paths must remain internal and
canonical; an optional single fragment is permitted, while schemes, queries,
absolute paths, traversal, controls, and backslashes are rejected.

Stable relocation is reported separately.  =user= is true only when the
coalesced location followed direct wheel, pointer, or touch activity:

#+begin_src json
{"kind":"event","event":"location","view":1,"user":true,
 "location":{"cfi":"epubcfi(/6/4!/4/2)",
             "href":"OPS/chapter.xhtml","fraction":0.2}}
#+end_src

Foliate follows internal EPUB anchors itself.  An explicit click on an
external anchor is canceled inside the child and becomes a semantic event
containing its resolved absolute URI:

#+begin_src json
{"kind":"event","event":"external-link","view":1,
 "uri":"https://example.com/reference"}
#+end_src

The URI must have an explicit scheme, contain no spaces or controls, and fit
within 4,096 UTF-8 bytes.  JavaScript, Rust, and Emacs validate it
independently.  WebView2 new windows remain denied; only Emacs may pass an
allowlisted scheme to =browse-url=.

=view-create= accepts a logical =view= ID, a live Emacs frame HWND as
=parent=, a physical-pixel =bounds= object, and optional =visible=.  The
current spike loads only its built-in local HTML page.

#+begin_src json
{"id":1,"op":"view-create",
 "params":{"view":1,"parent":1902902,
           "bounds":{"x":968,"y":0,"width":944,"height":988},
           "visible":true}}
#+end_src

=view-bounds= moves or resizes one child, =view-visible= changes its
visibility, =view-focus= gives it native focus, and =view-focus-parent= gives
focus back to its parent.  =view-clear-selection= asks the trusted renderer to
remove the active publication DOM selection, and =view-destroy= removes the
child.  =view-status= reports whether the built-in page finished loading,
together with the last accepted bounds and visibility.

The helper emits =focus-gained= and =focus-lost= from WebView2's controller
events.  Emacs selects the surface's owning window on entry and requests
=view-focus-parent= when another Emacs window becomes selected.
=SPC= and =M-m= also return focus before Emacs queues the normalized key, so
the native child does not need to reproduce Emacs prefix-map state.

Chromium paints EPUB text selection directly inside the current Foliate spine;
Yunge does not build a second highlight layer.  Once pointer or keyboard
selection settles, the renderer emits its canonical spine href and two
collapsed EPUB CFI endpoints.  A collapsed selection is an explicit null:

#+begin_src json
{"kind":"event","event":"selection","view":1,
 "selection":{"href":"OPS/chapter.xhtml",
              "start":"epubcfi(/6/4!/4/2/1:0)",
              "end":"epubcfi(/6/4!/4/2/1:7)"}}
{"kind":"event","event":"selection","view":1,"selection":null}
#+end_src

The href and each CFI are limited to 3,072 UTF-8 bytes and independently
validated by the renderer, Rust, and Emacs.  Endpoints must differ, hrefs may
not contain fragments, and selection state belongs to one logical view.  A
surface replacement clears it.  The current scrolled paginator owns one
iframe, so this contract deliberately describes one-spine ranges; it does not
silently approximate cross-spine selection.

=view-selection-text= resolves only the exact selection still owned by the
view and returns Chromium's =Range.toString()= text in bounded Unicode
character batches.  Its response is asynchronous and keeps the original
request ID; unrelated view events may be written first.

#+begin_src json
{"id":4,"op":"view-selection-text",
 "params":{"view":1,
           "selection":{"href":"OPS/chapter.xhtml",
                        "start":"epubcfi(/6/4!/4/2/1:0)",
                        "end":"epubcfi(/6/4!/4/2/1:20000)"},
           "offset":0,"character-limit":16384}}
{"id":4,"ok":true,
 "result":{"text":"...","total":21000,
           "next-offset":16384,"done":false}}
#+end_src

The numeric offset is a transient cursor into this one selection, not a
durable EPUB position.  A completed batch omits =next-offset=.  One batch is
limited to 65,536 characters, the complete selection to 1,048,576
characters, and the callback JSON to 512 KiB.  Rust independently checks the
returned character count, cursor progression, completion flag, total, field
set, error code, and byte size.  Changed or cleared selections fail instead
of copying text from a stale range; oversized selections fail rather than
being truncated.

=view-search= performs bounded literal discovery without creating renderer
annotations.  It returns stable same-spine CFI endpoints and compact context
for each match.  The asynchronous response keeps the original request ID.

#+begin_src json
{"id":5,"op":"view-search",
 "params":{"view":1,"query":"Chapter","case-sensitive":false,
           "direction":"forward","origin":null,"cursor":null,
           "match-limit":64,"section-limit":8}}
{"id":5,"ok":true,
 "result":{"matches":[
   {"href":"OPS/chapter.xhtml",
    "start":"epubcfi(/6/4!/4/2/1:0)",
    "end":"epubcfi(/6/4!/4/2/1:7)",
    "text":"Chapter","before":"A ","after":" title"}],
   "cursor":{"href":"OPS/chapter.xhtml","offset":1},
   "done":false}}
#+end_src

One request returns at most 200 matches and searches at most 64 searchable
spine items.  Queries contain 1--256 Unicode characters.  =direction= is
=forward= or =backward=.  An optional durable =origin= uses href and CFI;
=origin= and =cursor= are mutually exclusive.  The cursor href is canonical,
and its nullable offset is a transient directional match boundary within that
spine, not a durable EPUB position.  Results are nearest-first in the requested
direction.  A completed batch omits =cursor=.
The renderer caps its response at 384 KiB, while the native IPC boundary
accepts at most 512 KiB.  Rust independently validates every field, CFI range,
result count, cursor advance, error code, and byte bound.
This operation only discovers results.  Navigation and visible search paint
remain separate view behavior.

=view-search-result= applies that separate view behavior to one current
match.  A non-null selection must carry same-spine href, start CFI, and end
CFI fields.  The renderer verifies that both CFIs resolve into the claimed
spine, builds one range CFI, navigates through the coalescing view scheduler,
and paints only that range in Foliate's SVG overlayer.

#+begin_src json
{"id":6,"op":"view-search-result",
 "params":{"view":1,"selection":
   {"href":"OPS/chapter.xhtml",
    "start":"epubcfi(/6/4!/4/2/1:0)",
    "end":"epubcfi(/6/4!/4/2/1:7)"},"reveal":true}}
{"id":6,"ok":true,"result":{"view":1,"selection":true}}
{"id":7,"op":"view-search-result",
 "params":{"view":1,"selection":null,"reveal":false}}
#+end_src

The logical view retains the desired current result while its native surface
is hidden.  A newly selected result uses =reveal=true= to move before paint.
A recreated surface uses =reveal=false= after =publication-ready=, restoring
the overlayer without overriding the independently restored reading place.
Search paint is independent of the Chromium selection: ESC and C-g clear both
transient layers while Reader keeps the query and discovered results, and n/N
shows the current search range again before moving through those results.
While discovery is outstanding, Reader retains one latest navigation intent
instead of queuing repeat keys.  A direct reading movement detaches the old
run; its one in-flight batch cannot reveal a result, and the next n/N starts
from the new stable reading location.  A dismissal cancels only the delayed
reveal and hides transient paint, retaining the current search run.

Emacs maps the same href and CFI endpoints into Reader's logical selection.
Focused =y= is a normalized renderer key event that reaches the owning
buffer's active keymaps; Reader then drives these bounded batches and updates
the kill ring only after the complete selection succeeds.  Native =C-c= is
not intercepted and remains available to WebView2.

=view-navigate= accepts =previous-line=, =next-line=, =previous-screen=,
=next-screen=, or =go-to=.  A =go-to= target may be a complete stable locator
or a bounded href-only outline target.  Href-only targets are transient: the
helper and Emacs do not promote them to a saved location.  A later =location=
event supplies the complete CFI, canonical spine href, and fraction that the
owning view may persist.

The renderer runs at most one navigation operation and retains only the latest
pending intent.  Repeated keys can therefore continue moving through the book
without building an unbounded queue.  A newer direction or =go-to= target
replaces older pending movement.  Line movement uses the loaded document's
computed line height without animation.  Screen movement within a loaded
spine item uses Foliate's bounded 300 ms ease-out animation.  Either scale can
cross a linear spine-item boundary, which may pause while the next item loads.
Moving beyond either end is a no-op, and unsuccessful movement releases the
renderer lock for later navigation.

=<escape>=, =C-g=, Control reader keys, and non-character reader keys are
captured by the native WebView2 accelerator event.  Reader character keys,
including =j/k=, =J/K=, the three zoom keys, and =y=, are relayed by the trusted
renderer because WebView2 does not classify them as accelerators.  Both paths
write unsolicited events without request IDs:

#+begin_src json
{"kind":"event","event":"accelerator","key":"<escape>","view":1}
{"kind":"event","event":"accelerator","key":"C-g","view":1}
{"kind":"event","event":"accelerator","key":"C-d","view":1}
{"kind":"event","event":"accelerator","key":"j","view":1}
{"kind":"event","event":"accelerator","key":"J","view":1}
{"kind":"event","event":"accelerator","key":"+","view":1}
{"kind":"event","event":"accelerator","key":"y","view":1}
{"kind":"event","event":"accelerator","key":"SPC","view":1}
{"kind":"event","event":"accelerator","key":"M-m","view":1}
{"kind":"event","event":"focus-gained","view":1}
{"kind":"event","event":"focus-lost","view":1}
#+end_src

The helper accepts only =j=, =k=, =J=, =K=, =+=, =-=, ===, =y=, =SPC=,
=M-m=, =C-d=, =C-u=, =C-g=, =<escape>=, =<next>=, and =<prior>=.  It never
interprets them as commands.  Emacs resolves reading keys through the owning
EPUB buffer's active maps.  Leader keys return focus and re-enter Emacs's input
loop; after =<escape>= or =C-g=, the child also returns focus to its owning
Emacs window.

The ready handshake carries that exact normalized accelerator list.  Rust also
passes the renderer-owned subset to JavaScript when opening a publication.
Lisp, Rust, and JavaScript keep independent allowlists and reject contract
drift before routing a key.

View IDs are independent, so multiple Reader views do not share layout or
scroll state.  Positions must be nonnegative; dimensions must be positive and
at most 32,768 physical pixels.  Duplicate views, unknown views, invalid HWNDs,
unknown parameters, and unavailable runtimes return stable protocol errors.

The helper pumps native messages on its main thread while a background thread
reads stdin.  =shutdown= and EOF drop every child view and publication before
exit.  This mode is Windows-only until equivalent parent ownership is
implemented and tested for WKWebView and WebKitGTK.

* PDF operations

=pdfium-info= loads the configured library and reports backend, API, and
library path.

=open= accepts an absolute local =path= and optional =password=.  It returns
an opaque process-local =document= handle, =fixed= layout, =page-count=, and
canonical geometry for every page.  Lightweight geometry lets Emacs build a
stable virtual roll without rasterizing the complete document.

A =document= handle belongs only to the helper process that returned it.
Replacement processes may reuse the same number, so clients must reject old
handles before writing a request to a new helper session.

If PDFium rejects an absent or incorrect password, =open= fails with the
stable code =pdf-password-error=.  The password is request-only data: the
helper neither returns it in a response nor writes it to diagnostics.

#+begin_src json
{"id":3,"op":"open",
 "params":{"path":"C:/books/example.pdf"}}
{"id":3,"ok":true,
 "result":{"document":1,"layout":"fixed","page-count":12,
           "pages":[{"page":0,"width":595.276,"height":841.89,
                     "label":"1"}]}}
#+end_src

=page-info= accepts =document= and a zero-based =page=.  It returns canonical
PDF point width and height plus the page label.  The dimensions describe the
visible page bounding box after the crop box and intrinsic page rotation are
applied, matching =render-page=.

#+begin_src json
{"id":4,"op":"page-info","params":{"document":1,"page":0}}
{"id":4,"ok":true,
 "result":{"page":0,"width":595.276,"height":841.89,"label":"1"}}
#+end_src

=outline= accepts a =document= handle.  It returns bookmarks in bounded
preorder with a zero-based =depth=.  A structural bookmark has a null
=destination=.  A local destination contains a zero-based page, optional
canonical PDF =x=, =y=, and =zoom= values, plus its PDF view kind.  Coordinates
are relative to the visible, intrinsically rotated destination page.

#+begin_src json
{"id":5,"op":"outline","params":{"document":1}}
{"id":5,"ok":true,
 "result":{"items":[
   {"title":"Chapter 1","depth":0,
    "destination":{"page":2,"y":700,"view":"fit-horizontal"}}],
   "truncated":false}}
#+end_src

The helper returns at most 10,000 entries and at most 1,024 Unicode
characters per title.  =truncated= is true when traversal reaches the entry
limit or detects a bookmark cycle.  View kinds are =xyz=, =fit=,
=fit-horizontal=, =fit-vertical=, =fit-rectangle=, =fit-bounds=,
=fit-bounds-horizontal=, =fit-bounds-vertical=, and =unknown=.  Outline
extraction does not expose or execute URI, remote-document, embedded-document,
Launch, or unsupported bookmark actions.

=page-links= accepts a =document= and zero-based =page=.  It returns at most
4,096 links with canonical PDF bounds relative to the visible, intrinsically
rotated page, an optional label of at most 256 Unicode characters, and one
tagged action.

#+begin_src json
{"id":6,"op":"page-links","params":{"document":1,"page":0}}
{"id":6,"ok":true,"result":{"page":0,"links":[
  {"bounds":{"left":72,"bottom":700,"right":144,"top":712},
   "action":{"type":"location",
             "destination":{"page":2,"view":"fit"}}},
  {"bounds":{"left":72,"bottom":680,"right":180,"top":692},
   "action":{"type":"uri","uri":"https://example.com"}}],
  "truncated":false}}
#+end_src

URI actions require an explicit ASCII scheme, contain no whitespace or control
characters, and are limited to 4,096 UTF-8 bytes.  The helper does not choose
allowed schemes and never opens a URI.  Remote-document, embedded-document,
Launch, and unsupported page actions are filtered.

=page-text= accepts =document= and =page=.  It returns the complete Unicode
text plus characters in PDFium index order.  Each character has a zero-based
=index=, Unicode =text=, nullable canonical =bounds= and =quad= geometry, plus
=generated= and =hyphen= flags.  PDF coordinates start at the bottom left of
the visible, intrinsically rotated page, matching =render-page=.  The four
=quad= vertices follow the transformed glyph axes in outline order.  Clients
use =bounds= only when =quad= is null and reject malformed non-null quads.

#+begin_src json
{"id":5,"op":"page-text","params":{"document":1,"page":0}}
{"id":5,"ok":true,
 "result":{"page":0,"text":"Introduction",
           "characters":[{"index":0,"text":"I",
             "bounds":{"left":72,"bottom":700,
                       "right":78,"top":712},
             "quad":[{"x":72,"y":700},{"x":78,"y":700},
                     {"x":78,"y":712},{"x":72,"y":712}],
             "generated":false,"hyphen":false}]}}
#+end_src

PDFium exposes axis-aligned character bounds and a separate effective text
matrix.  The helper combines their extents to recover the oriented rectangle.
At singular absolute-axis angles such as 45 degrees, font ascent and descent
constrain the otherwise ambiguous width and height.  Generated separators and
unrecoverable geometry keep =quad= null without removing their text index.

=search= performs a directional Unicode literal search.  It accepts
=document=, nonempty =query=, optional =case-sensitive=, required =direction=,
an optional stable =origin=, an optional transient =cursor=, and bounded
=match-limit= and =page-limit= values.  Origin and cursor are mutually
exclusive.  The default limits are 64 matches and eight pages; their maximums
are 200 and 64.

Each result contains inclusive stable =start= and =end= positions, exact
matched =text=, and bounded =before= and =after= context.  Results are ordered
nearest-first in the requested direction.  A cursor has a zero-based page and
a nullable PDFium character boundary; null means the directional page edge.
It is null exactly when =done= is true.  A client can therefore interleave
search batches with rendering and stop when a run becomes obsolete.

#+begin_src json
{"id":6,"op":"search",
 "params":{"document":1,"query":"Introduction",
           "case-sensitive":false,"direction":"forward",
           "origin":{"page":0,"offset":2},
           "match-limit":64,"page-limit":8}}
{"id":6,"ok":true,
 "result":{"matches":[{
   "start":{"page":0,"offset":3},"end":{"page":0,"offset":14},
   "text":"Introduction","before":"1  ","after":" Overview"}],
   "cursor":{"page":8,"offset":null},"done":false}}
#+end_src

Queries longer than 256 Unicode characters are rejected.  Search does not
interpret regular-expression syntax and does not join matches across page
boundaries.  Case-insensitive matching uses Unicode-aware simple case folding.

=selection-text= accepts two inclusive document positions and an optional
=cursor=.  Each position has a zero-based =page= and PDFium character =offset=.
The helper normalizes backward selections.  =page-limit= defaults to 8 and is
bounded at 64; =character-limit= defaults to 16,384 and is bounded at 65,536.
Each response returns directly concatenable =text=, the next =cursor=, and
=done=.  A continuation within one page adds no separator; a continuation on
the next page begins with the one newline belonging to that page boundary.
Invalid pages, offsets, cursors, or limits return stable protocol errors.

#+begin_src json
{"id":7,"op":"selection-text",
 "params":{"document":1,
           "start":{"page":1,"offset":4},
           "end":{"page":0,"offset":3},
           "page-limit":1,"character-limit":12}}
{"id":7,"ok":true,
 "result":{"start":{"page":0,"offset":3},
            "end":{"page":1,"offset":4},
            "text":"first page t",
            "cursor":{"page":0,"offset":15},"done":false}}
#+end_src

=render-page= additionally accepts pixel =width= from 16 through 8192 and a
64-character lowercase hexadecimal =cache-key=.  The helper alone maps that
key to =YUNGE_READER_CACHE/<key>.png=.  It returns the absolute path, pixel
dimensions, and whether an existing valid cache entry was reused.  Reusing an
entry refreshes its cache-pruning recency on a best-effort basis.

#+begin_src json
{"id":8,"op":"render-page",
 "params":{"document":1,"page":0,"width":1000,
"cache-key":"0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"}}
{"id":8,"ok":true,

=close= accepts a =document= handle and deterministically drops its PDF state.

* Shutdown and ownership

Emacs requests graceful shutdown with:

#+begin_src json
{"id":9,"op":"shutdown"}
{"id":9,"ok":true,"result":{"stopped":true}}
#+end_src

Before responding, the helper drops all open documents.  It then flushes the
response and exits successfully.  Closing stdin also drops documents and
exits successfully.

The process owns one lazy PDFium instance.  Documents borrow that instance and
are explicitly removed on =close= or =shutdown=.  The singleton itself lives
for the helper process lifetime because the underlying bindings are global;
the operating system reclaims it at process exit.
